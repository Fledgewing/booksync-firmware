# BookSync firmware checks

`check.yml` is the only firmware workflow. It runs on pull requests into `main`
and pushes to `main`, with a read-only token and no signing or publication steps.
`BookSync firmware check` aggregates host tests and all six profile jobs; require
that check when configuring branch protection. Artifacts are test evidence only.

Run `python3 tools/ci/host.py`, then `pio run -j 2 -e <profile>` for each of
`x4-pro`, `x4-classic`, `default`, `x4-pro-simulator`, `x4-classic-simulator`, and
`simulator-X3`. Build profiles serially within a checkout. Use a separate
`PLATFORMIO_CORE_DIR` when sharing a machine with another build. Never use upload
or monitor targets for these checks. Hardware acceptance is maintainer-only.

For each hardware build, retain its output in `reports/<profile>.log` and run
`python3 tools/ci/measure.py <profile>`. This calls the unchanged PR #200 parser,
validates the two app partitions, requires image/ELF/map/partition artifacts, and
records static sections, sized symbols and input hashes. The full map and sorted
symbol list permit comparisons with the previous successful run; no runtime RAM
or map delta is inferred from application image bytes. Compare identical inputs
and toolchains. The baseline records its host OS; cross-host deltas are diagnostic. Host heap/stack metrics cannot qualify ESP32 memory safety.

`budgets.json`, `size_report.py`, `test_size_report.py`, and `simulator.json` are
byte-for-byte mirrors of BookSync PR #200, merge
`d457a19b805eaa8099f42a8b11a475da28e602d7`. CI checks equality against that immutable
source using `check_shared.py`. Update both repositories together and advance the
source ref when changing that contract; never maintain a second independent
threshold. The original parser fixtures cover all devices, the exact reserve
boundary, a failing image and missing RAM summaries; harness fixtures add missing
artifacts and mismatched partitions.

`python3 test/simulator/boot.py <simulator-profile>` runs the existing isolated
synthetic SD/EPUB boot and two-page reader smoke once, without retries. It retains
logs, timings and available framebuffer captures. F02 establishes the pinned
baseline, not later Library/Home, transport or migration scenarios. Add those
scenarios as their slices land. No new UI or reader behavior is introduced.

Before F01 lands, both boundary guards may be absent. Once either guard or
`module-layers.json` exists, both guards are mandatory and their failures fail CI.
The guards own inventory and rejection-fixture self-tests. Later host tests added
to the root CMake suite automatically join this gate.

On hardware, the maintainer should sideload the matching test image on X4 Pro,
X4 Classic and X3/C3 X4, open a local EPUB offline, turn pages, return Home and
resume. Expect unchanged native reading and saved position. F02 changes no cache
format and needs no cache reset. No release or device acceptance is implied.

F05 adds `retired_writers.py` to hardware measurements and simulator startup.
It rejects native writer symbols and archived map objects. The simulator suite
also runs `native_writers_retired.py` with an audited fake socket/DNS transport,
legacy account flags and delivery subscriptions enabled. Four positive probes
prove interception; the reader must save progress, stats and local event capture
with zero requests. See `docs/booksync/F05.md` for scope and hardware verification.

F14 adds `size.py` and the committed `size.baseline.json`. `measure.py` requires
that baseline, reports image/static-RAM/section deltas and the complete built
partition table, and rejects any partition-map change. Growth itself does not
fail CI: the shared reserve gate remains authoritative. `size-detail.json` keeps
all section and allocated map-object deltas, plus sized-symbol deltas for the
largest 50 symbols and every owned BookSync/Tailnet symbol; raw sorted symbols and complete maps remain in the
artifacts. Map guards demangle actual map symbols as well as checking excluded
objects and ELF symbols. Measurements also require linked native capture, journal,
MicroLink and TLS entry points, so an accidentally stripped pipeline cannot pass.
Object totals exclude linker fill and generated bytes;
the physical image is measured independently. Baselines are measured, never
inferred from map text size.
To refresh, run `measure.py <profile> --collect-baseline` for each real device
(the reserve and map guards still run), then explicitly run
`python3 tools/ci/size.py --record-baseline` and rerun ordinary measurements.
Review the inputs and toolchain before accepting a refresh;
CI never rewrites its own baseline. The shared PR #200 files remain unchanged.

`test/simulator/size_gate.py <profile>` joins native page-turn capture, an abrupt
process exit, torn staging recovery and reading refusal/Home fake-worker admission
in two boots on the same synthetic SD. `boot.py` requires it in each of the three
simulator jobs; the aggregate check therefore requires all six builds and all
three end-to-end gates. No failing process is retried. Per-boot `metrics.json`
records native peak RSS and elapsed time separately from unavailable ESP32 heap,
largest-block and stack-watermark fields. It also requires the exercised worker
to report its bounded requested-allocation peak. RSS includes reader/SDL/allocator
costs and cannot qualify embedded RAM.

Maintainer hardware verification: on X4 Pro, X4 Classic and X3/C3 X4, open a local
EPUB offline, turn pages, restart and reopen at the saved native position. From
Home exercise connection/cancel/reconnect, then confirm reading refuses admission
without losing its display or position. Inspect internal free/largest RAM and
worker stack-watermark logs, including C3 display release/restoration. Expect no
native upload requests. No cache format changes or cache reset are needed. Agents
must not flash devices or open serial ports.

F18a adds `test/simulator/lifecycle_match.py` to each profile boot gate: eight
match-only scenarios, five abrupt exits and 25 boots against a durable fake
server, using F15 accounts and the F17 owner. The dormant handler is retained in
all real images for size measurement. No real outgoing lifecycle delivery is
enabled. See `docs/booksync/F18a.md` for the checkpoint and hardware checks.

F18d adds `test/simulator/lifecycle_state.py` to each boot gate: eleven state-phase
scenarios, seven deliberate abrupt exits and 34 boots per profile. It proves
remote commit/reconciliation, pending-checkpoint restart, deferred native
writeback and dedup using the production F17 owner and real HAL, with independently
persisted fake remote/native receipts. See `docs/booksync/F18d.md` for bounds,
private seam contracts and maintainer-only hardware verification.
F18c adds `test/simulator/lifecycle_annotations.py` to every profile boot gate: 13
annotation/bookmark scenarios, eight abrupt exits and 40 boots against separately
persisted fake server, workspace and synthetic native annotations. Hardware images
retain the dormant phase for reserve measurement. See `docs/booksync/F18c.md`.
