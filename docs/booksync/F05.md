# BookSync F05 — native writer retirement

F05 removes native progress/account, stats, clippings, nearby-state and plugin
network delivery from the linked firmware. No BookSync server writer is introduced.
Home and general boot ownership remain F04's responsibility; persisted native
sync/auth boot targets cannot reactivate a retired writer.

The shared `booksync-retired` source filter excludes the archived activity/client
implementations from both hardware and simulator profiles. The build middleware
also excludes the native transport translation unit discovered through the local
library. Sources remain inventoried for provenance and later read-only format
extraction. Neither a settings flag nor a disabled preprocessor branch enables them.

Removed routes include reader menus, quick actions, native account/sync settings,
folder/book upload, File Transfer's server/nearby-state sync actions, the plugin
catalog entry, the portal's outbound relay and USB progress/extras proxy. Ordinary
USB file operations, USB Drive, Wi-Fi primitives and nearby book transfer remain.
Old shortcut values and stored records retain their native meanings on disk;
retired actions cannot launch a network writer.

Local position saving, stats/checkpoints, clippings/bookmarks and best-effort plugin
outbox capture remain. Sleep still calls reader preparation and captures its event,
then continues the existing screen/storage/power sequence without connecting or
draining. No binary cache format changes or cache reset are required.

Stats identity is extracted unchanged from the GPL native sync client into
`StatsIdentity`: the existing simulator identity and hardware-derived prefix/bytes
continue to select exactly the same local stats files. `loadStored` names the
existing checked local stats loader without suggesting a delivery operation.
No new production heap allocation is introduced; the identity formatter uses a
six-byte local array. Existing bounded event-capture allocation is retained.

## Verification

- `python3 tools/ci/host.py`: retained production/fault tests plus F05 source,
  build-exclusion and real hidden-symbol rejection fixtures. The source check also
  scans disabled preprocessor branches and retained inline headers.
- `python3 tools/ci/measure.py <hardware-profile>`: requires actual image/ELF/map
  artifacts, enforces the unchanged 131,072-byte reserve and rejects retired linked
  symbols or object files. Source inventories continue to scan archived inputs.
- `python3 test/simulator/boot.py <simulator-profile>`: retained boot/reader cases
  plus F05's connected-fake-radio reader session with legacy account flags and
  immediate-delivery subscriptions enabled. A fake socket/DNS transport refuses
  and counts attempts; four positive controls must be observed before the session.
  The session must save local progress/stats and open/exit/sleep outbox records with
  zero requests. Each scenario executes once; a failure stops the suite.

The simulator does not represent ESP internal heap, largest allocatable block,
PSRAM admission or FreeRTOS stack high-water accurately. Native host memory is not
hardware acceptance. This slice removes delivery work and introduces no additional
firmware buffer or task.

Maintainer hardware check, on X4 Pro, X4 Classic and X3/C3 X4: open a local EPUB,
turn pages, save a clipping/bookmark, close/reopen, then sleep/resume. Expect the
same page/anchor and local stats/annotations, no sync/account screen, no plugin
network delivery or radio connection at sleep. Check serial/network evidence only
as a maintainer; agents do not touch devices or serial ports.
