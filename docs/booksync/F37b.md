# F37b account presentations

The maintainer approved all eleven F37a account states on 2026-11-27 (~21:40 PT).
The approval record is BookSync PR #238. The service picker now replaces itself
with the account form after Continue selects a service; local saved books and
Later still return without a login. Setup/Settings activation of the existing
picker remains separate from this explicit navigation seam.

The approved scene IDs are account-out, account-in, account-limited,
account-manual, account-busy, account-phone, account-wait, account-expired,
account-failed, account-two-step and account-old. All three profiles share the
controller and bounded Library value/intent contract. Rendering uses cached
values only; no Library read, parsing, encoding, filesystem or auth call occurs
in paint. SDK keyboard tables supply the letter/symbol layouts and controls;
button focus and touch hit testing use the same geometry. The touch keyboard is
bottom docked, below the fields and actions. Passwords always draw a fixed mask;
input is erased with volatile writes on submission, cancellation, epoch retirement
and destruction. Input never enters a display snapshot or log.

A form is scoped by its Library-issued form ID and account epoch. A correlated
successful authentication can adopt its new epoch only while the form is live
and the current Library account matches that result. External account changes,
including A-to-B-to-A, retire the form. Closed forms perform no further Library
reads, dispatch or paints. Back/Cancel closes presentation; worker-owned results
cannot navigate or reopen it. Phone Check is an explicit intent, never a polling
timer. The complete public approval link supplies both the version-10 QR and the
readable wrapped link; QR preparation happens outside paint. Library publishers
must validate and redact approval URLs before publishing them, and never publish
credentials, private challenge handles or server responses.

This slice implements presentation and the Library form contract. It does not
invent an authentication protocol or activate the deliberately offline adapter.
The default Library honestly renders account-limited for its retained-connector
adapter; it refuses account-capable claims without an integrated account service.
The synthetic Library exercises all approved states and asynchronous results.
Independent sync/acquisition forms, account-origin changes and sign-out
confirmation remain F37c. Reader behavior, caches, partitions and the sole sync
writer are unchanged.

The offline facade adds one <=368-byte static public form and an 8-byte counter.
The controller is bounded to 2 KiB; the foreground activity, including a 512-byte
QR workspace, is bounded to 4 KiB. ActivityManager makes one fallible lifetime
allocation because these buffers exceed the small task stack; no per-key or
per-paint allocation, network task or extra framebuffer is added. The existing
QR library uses roughly 1.2 KiB of bounded temporary encoder arrays at version 10;
encoding therefore runs on the main-loop stack, outside the render task. Native RSS is
reported separately from unavailable ESP32 heap, largest-block and stack metrics.

Run the host gate, all six profile builds, all three simulator boot suites and
hardware size measurements as described in tools/ci/README.md. The dedicated
account_forms scenario captures all eleven scenes through the real ActivityManager,
including navigation from the picker, and checks no service work during paint
and no late repaint after Back or an epoch change.

Maintainer-only hardware verification: on X4 Pro, Classic and X3/C3 X4, enter the
service picker through its explicit setup/settings integration seam. Continue to
the supported account state, exercise touch or Previous/Next/Select, and Back to
saved books. With an authorized account-service fixture, check manual Server/User/
Password entry (including symbols), bottom-docked Pro keys, fixed password mask,
QR scanning and the matching complete readable link, manual Check, all errors and
Cancel during pending sign-in. A delayed result must never reopen a closed form.
Inspect internal free/largest heap and task stack watermarks. Open/resume an EPUB
before and after the flow and verify the same native reading position. No cache
reset is required. Agents do not flash devices or access serial ports.
