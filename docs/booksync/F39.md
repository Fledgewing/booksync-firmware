# F39: personal providers and reading-stat coverage

F39 adds worker-only selection and statistics policy. It adds no screen, UI
method, scan on paint, new writer or outgoing activation. Widget projections
and renderers join this policy in their own F40 slices.

The semantic references are BookSync's companion `PersonalReading.kt` and
`ReadingStats.kt` on `origin/feature/0.12` (read at `25f8298fee235eeb896d1093caecb386935cc263`).
The C++ implementation is independent. The firmware PLAN's slim upgrade decision
supersedes the old F27c import: there is no legacy stats import. Native files
remain untouched. Pre-0.12 account history can come only from the normal first
server sync, subject to what the server retained. Missing history is not zero.

## Saved provider selection

`PersonalReadingSource` supplies a frozen, neutral saved snapshot, its capability
state and owner/epoch. No acquisition runs here. A failed provider discards its partial pool and restarts selection over the remaining providers (at most eight retirements). Providers own record content and
saved rank; registration order owns precedence. Exact identities shared by native
and catalog providers deduplicate; indexed `find` returns the first ordinal,
including repeats within a provider. Hashes never substitute for identity checks.
The snapshot/index must stay immutable for the batch. Account invalidation must
retire the worker batch before its result is published, just as F21 retires its
materialization. Caller-owned providers and their pointer array outlive the run.

Card fields fill in registration order; known zero is a value. Missing fields
fall through. Highlight uses floor-modulo of the device-local epoch day; Year ago
and Recommended retain the first saved rank. Discover hashes `day:identity` with
SHA-256 and selects the clamped pick modulo the deduplicated count in ascending
digest order, matching the companion's cycle across restarts. Saved native picks
carry `ThisReader` coverage; account picks carry `Account` and owner/epoch.
Unsupported, off, not saved, empty, failed and oversized remain distinct.

C3 cannot retain 10k decoded records plus rank strings. Selection uses two fixed
record buffers, a 256-counter radix histogram and bounded cursors. Discover takes
at most 33 passes (ending early once a rank prefix is unique); each tick reads at most 32 rows, with at most eight indexed
identity lookups per row. The tradeoff is repeated saved reads/hashing rather
than catalog-sized RAM. Providers must supply an indexed lookup, not a hidden
catalog crawl per lookup. No allocation, vector, JSON tree or full-catalog sort
is introduced. Duplicate callers can share one worker batch/result.

## Statistics and watermarks

`PageStatsSource` freezes F18b's durable page-row count and closes files between
calls. `ReadingStats` consumes only timed page intervals, never native cumulative
book totals or F09 session summaries. Overlapping intervals contribute their
union; sessions join intervals separated by at most five minutes and exclude the
gaps. Durations clip to now and 24 hours. Gaps and reversed clocks mark capture
incomplete and disable pending reconciliation. Cursor/calendar failure discards
partial output. Fixed 32-row ticks yield to input.

The source supplies capture coverage, not a guessed first-event date. A caller
must prove uninterrupted capture from `since` through the snapshot. Oldest rows,
upload acknowledgments and successful file recovery do not prove coverage. Days
before coverage remain absent, even when there are no saved rows. Observed
values retain the explicit partial coverage label. Local streaks stop at unknown
days; fixed run counters cover the entire captured history independently of the
365-day calendar display. Both streak fields retain local coverage.
The default calendar is an explicit fixed UTC offset. A device calendar callback
can supply historical DST-aware day boundaries; UI never groups timestamps.

`RemoteReadingStats` is a neutral saved account value; `ServerAdapter` exposes an
optional cached reader with an absent default. Adapter acquisition/normalization
must supply per-day known flags and exact-snapshot inclusion evidence. F18b's
last accepted upload tuple is deliberately not promoted into such evidence.
Fetching a summary at a particular time proves no local inclusion.

Precedence is per field: saved account days, streak/best streak, goal and finished
counts win when available, including zero; absent fields retain local values.
A goal or completion count is never inferred from local pages. Local records
retain `ThisReader` coverage even with account days. Offline is independent of
saved data availability. Remote date windows align to the requested device day;
a stale last saved date cannot masquerade as Today. Unknown account days stay
unknown even with an inclusion watermark.

Today adds only the union of local events whose **start** is strictly newer than
an inclusive watermark. The pending calculation must echo that exact watermark,
be complete, match the account owner/epoch and requested day, and not be from the
future. Unbound native history cannot prove account inclusion. Without all this
proof, keep account Today and local Today separately, with separate coverage.
Never use max(local, remote), a fetch timestamp, or aggregate-plus-session sums.

## Memory, validation and hardware verification

Both services use fixed object storage; no new explicit heap allocation. The
stats accumulator and published result together stay below 13 KiB; the personal
selector below 7 KiB. Caller-owned output avoids large task frames. Instantiate
these workspaces only for the needed Home worker lifetime, release before reader
entry, and do not place them on a 2/4 KiB FreeRTOS task stack. Dormant code is
explicitly retained in real images so physical-size measurements include it;
this adds no resident service workspace before activation.

Hardware compilation gates these two service units at 256 bytes of compiler
reported stack usage per function and retains `.su` evidence in size reports.
This caught an aggregate output reset that generated a 6.4 KiB temporary on S3;
small member assignments replace that temporary. These static frames are not
runtime task high-water measurements or a claim about callees' total stack.

Host cases compile production services, page storage and publication. They cover
zero/absent, exact and missing watermarks, future proof, unknown days, account
isolation, native/account separation, midnight/DST callback, gaps, reversed clocks,
stream failures, 50k page events, provider precedence, duplicate identities,
capability states, SHA ordering and a 10k-row bounded Discover cycle. All three
simulator boot gates run seven offline scenarios over eight boots with real HAL
page persistence and normalized fake account snapshots. No network is needed.
Reports distinguish fixed object bounds from unavailable ESP32 internal heap,
largest block and task-stack high-water values.

Maintainer verification after service/activation wiring: on X4 Pro, X4 Classic
and X3/C3 X4, read a synthetic EPUB offline, pause/resume, close/reopen and reboot.
Expect unchanged native position, page input and counters. Compare a first fake
account sync with local-only history: zero and missing fields must remain distinct;
without exact inclusion proof keep Today separate; with proof count pending visits
once. Change accounts and ensure old account history disappears. Exercise clock
correction/full card and inspect explicit incomplete coverage, internal heap,
largest block and worker stack high-water (also PSRAM on S3). No EPUB cache reset
is required. Agents never access devices or serial ports; this is no release gate.
