# F36a — Library and lists

Targets the compact Library/list presentations approved by the maintainer on
2026-11-28 (~00:45 PT), using the revised integration-repository #249 gallery.
The integration-repository approval marker is owned by the coordinator and is
not changed here. This is not a release or device acceptance record.

The foreground controller lives in `ui/Catalog.*`. The runtime bridge in
`system/CatalogScreen.*` owns ActivityManager navigation, mapped input and cached
drawing. The UI-only contract compiles without private include paths or services.
Library exposes bounded count/source/file-choice values and intents only; no
adapter, credential, path, scanner, mutable job or competing sync writer enters UI.

Library uses two cover rows above four compact half-width number tiles. All count
links live at the header right. X3 uses the same source meanings as bounded text
and requests no cover artwork. Browse roots, scoped sources, grouped author/series
lists, contextual fractional/secondary membership, page cursors and nested Back
are shared. Grouping retains Android’s first-author/primary-series rule; secondary
memberships remain available through contextual Series queries. Group previews occupy the existing QueryEntry row budget. Metadata
labels do not change ungrouped sorting. A separate per-window file-truth array
prevents cached artwork or identity from implying a verified on-card file.

The 30 gallery variants are enumerated in `test/host/catalog_surface/SceneFixture.h`.
The simulator harness renders each through the production activity in every
profile and verifies that paint performs no Library work or automatic connection.
The fixture covers known/offline/missing/loading/error Library; Browse; Authors;
Series groups; On card; source lists and scopes; paging/Back; complete empty,
missing, incomplete and failed results; unsupported sources; file choices;
offline consent; preparing; known/unknown-length progress; failed/canceled jobs;
unsupported file/no-login/space/access; and verified local completion. Preparation
and failure stay inline; no new preparation, failure or success destination is
introduced. Detail and Series are Library handoffs to their separate F36b/F36c
owners, preserving this parent's cursor/focus. Child query owners cannot strand
the parent's single worker window on return.

Local files use the existing F13/F22 index and open resolver. The default offline
facade publishes only known on-card counts, never fake catalog totals or unknown
zeroes. Remote counts, saved source pages, cached file manifests, connection and
transfer operations remain capability/publication dependent. Their default ports
are unavailable until the separate live facade integration registers them; this
slice does not activate transport or add a writer. Filter/account/detail/Series
panels are handed to their existing public owners and are not reimplemented.

## Resources

One fallible controller allocation per foreground owner holds reused query,
window, choice and navigation buffers, bounded by a 32 KiB static assertion.
It is too large for the small task stack and cannot be static across overlapping
activity owners. Optional X4 thumbnails use at most eight 128×192 packed 1-bit
values (24.1 KiB), allocated once and released on exit; failure uses placeholders.
X3 allocates none. Acquisition requests yield in batches of four outside paint.
No second framebuffer or per-row/per-paint allocation is added. Query retirement
releases the optional F22 worker workspace rather than retaining it on Home.
The dashboard reuses idle query-result entries for eight last-good previews;
only bounded shelf descriptors are added, without another result/window allocation.
Back retires auto-open/presentation ownership and does not cancel durable work.

The unchanged F22 native stack gate remains <=256 bytes per frame. Native
measurements are not ESP task watermarks. Catalog request dispatch uses one
bounded 264-byte batch descriptor passed through the existing value API; its
native frame also includes the ABI's descriptor copy, and contains no row payload.
Simulator metrics record bounded requested UI allocations, elapsed time and native
peak RSS, with embedded heap/largest-block/watermark explicitly unavailable.

## Validation

Validation and physical-image/static-section deltas are recorded in the PR and
`reports/<profile>/`. The hard gate remains 131,072 free bytes in each
6,553,600-byte application slot. No partition, binary cache format or firmware pin
change is made. Generated translations are built from English YAML.

Maintainer hardware verification: on X4 Pro use touch to open Library, Authors,
Series, On card and a saved list, then page and return from a detail/Series owner.
On Classic and X3 repeat with focus/Select/Back; hold Confirm for Details/Series.
Confirm that Back preserves page/focus and the reader resumes at the exact native
position. With Wi-Fi off, local books must open immediately; remote selection
must request consent and Cancel must start nothing. Test known and unknown-length
jobs, cancel/resume, no space/access and Back before completion: no late open,
repaint over reading or restart. Check internal free/largest heap and task
watermarks on each device; simulator RSS cannot qualify this. No EPUB cache reset
is needed. Agents never flash devices or use serial ports.

## Visual correction and review evidence

The original functional scene checks did not establish visual parity. The visual
correction uses the approved 30-state Library gallery as the content/geometry
reference on all three profiles. It replaces proportional panels and generic
fixture labels with compact shelves/tiles, author/series order labels, removable
grouping, complete rows, readable file sizes and the approved inline/modal copy.
The saved source title remains part of the bounded navigation location, so paging
and nested Back cannot replace it with the root label. Error-state Filter and
Retry remain separate actions for both touch and buttons.

The shared Back capsule, round header icons, footer chrome, rounded actions and
row separators are owned by FK; the correction does not introduce a competing kit.
The paired review gallery labels these differences `chrome → FK`. Illustrative
footer arithmetic is called out separately: actual page counts are derived from
published totals and page sizes, rather than hardcoded sample numbers.

`test/simulator/catalog_surface.py` captures the production Activity and emits one
text-geometry trace per state. `catalog_geometry.py` checks every measured text
line against its slot, owning panel and screen and rejects overlaps within each
paint layer. Intentional modal/background occlusion is checked as separate layers.
The guard also rejects empty/exhausted traces. Its negative tests prove that
clipping, overlap and parent escape cannot silently pass. These checks supplement
visual review; they do not assert pixel parity or maintainer approval.

Generate a review gallery with `test/simulator/catalog_gallery.py --approvals
<approval-index.json> --reports reports --out <gallery-directory>`. It selects all
90 Library entries, copies their original approved PNGs, converts unmodified PGM
captures, retains hashes and text traces, and exports approved-left/capture-right
pairs. No personal photographs enter the repository. Synthetic cover artwork is
provided through the fixture Library cover port, not painted into product code.

The existing Activity allocation also retains 304 bytes of reusable formatting
scratch instead of nesting those buffers on the C3 render stack. There is no new
allocation, framebuffer, transport or worker. Real device heap/task-watermark
acceptance remains a maintainer check.

The geometry trace records the renderer's actual framebuffer dimensions; X3 is
528×792, while the approval is a 480×800 logical frame. Review pairs uniformly
fit the original approval into the physical viewport and link its unmodified PNG.
The guard rejects missing runtime dimensions instead of assuming a Pro-sized
screen. X3's shorter grouped rows and the approved empty/error action baselines
are tested through that same production path. Browser antialiasing and native
1-bit glyph/cover dithering remain visible in the unretouched comparison.
