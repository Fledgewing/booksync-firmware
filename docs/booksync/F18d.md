# F18d: lifecycle book state

BookSync independently ports the companion's state-phase behavior from
`android/companion/app/src/main/java/net/fledgewing/orbitcompanion/server/bookorbit/BookOrbitSync.kt:204–238`
at integration commit `7b3220fe6920180ffbbc34b9307508db71b6c893`.
The firmware implementation, protocol values and pending-response codec live in
`server/bookorbit/LifecycleState.*`. No companion or upstream server source text
is copied. This adds no screen or Finish intent; F20 still owns those intents.
The default adapter remains offline, as in F18a. Transport and native evidence
are injected private worker seams; real replay still needs F29 activation proof.

The handler requires F17's borrowed writer token, the completed F18a match and
preceding phase acknowledgements, F15 sync readiness, matching connector identity,
account scope and exact captured source revision. A changed account epoch after
transport leaves delivery uncertain. Read/unread/finished native status values
pass through without changing reader behavior. Ratings are 1–5; zero is an absent
capture. An absent rating becomes an explicit clear only if the same account and
document have a known previously nonempty rating. Review notes use the same rule,
including the distinction between an explicit empty string and no value.
Review modification falls back to the captured status modification timestamp.
Manual pending status is neither sent nor applied by background state sync.

F17's neutral `Checkpointed` outcome saves incomplete phase output through the
existing journal without acknowledging or advancing the phase. It preserves the
attempt marker; `PhaseStored` is an appended observer point for fault tests.
A new partial checkpoint reports `Advanced` so a drain can continue; unchanged
partial output is rejected rather than spinning or falsely acknowledging work.
A successful exchange first yields this outcome with an adapter-private `BSS1`
checkpoint containing the complete response and original F18a checkpoint. A
subsequent owner step applies it only after the native book closes. Native status
is suppressed if its token changed; the evidence provider must also recheck the
source, open-book exclusion and token atomically with durable native publication.
The provider preserves unrelated native fields, records same-account rating/review
history flags even when a reply makes them unknown, and
must make repeat publication harmless if power fails before the phase ack. A
failed publication retains the saved reply without another exchange. The final
ack restores the original matched checkpoint for F18e. An entirely empty/unknown reply has
no local effects and can be acknowledged directly.

An uncertain exchange must recover the original response or prove noncommit
before resending the unchanged capture. The private transport contract forbids
blind replay, overwriting newer remote state during reconciliation, fabricated
acknowledgements and invented protocol idempotency headers. Fake transports model
this contract with independently persisted remote state. This slice does not
claim a live-server reconciliation endpoint exists or enable outgoing delivery.

## Bounds and recovery

The journal envelope version and EPUB cache formats are unchanged. `BSS1` is an
adapter-private tagged checkpoint inside the existing checksummed envelope; its
layout is documented in `docs/file-formats.md`. Unsupported or corrupt pending
bytes remain queued. No new heap allocations, task or steady-state buffer are
introduced. The worker supplies the existing 1024-byte output capacity and
5504-byte owner scratch; temporary state consists of borrowed views and identity
values rather than review copies. Host `sizeof` measurements are StateInput 280 B, StateValues 64 B,
StateQuery 96 B and MatchCheckpoint 120 B (64-bit host, not ESP32 ABI); the largest local input is justified by its immutable
borrowed views rather than introducing persistent buffers or heap churn.
Native/network worker stack measurements still
require hardware acceptance. Captured reviews are bounded to 10000 bytes, matching
the companion; the complete remote reply plus original match must fit the smaller
journal checkpoint. Oversize replies remain uncertain, with no truncation or ack.
This is an explicit capacity refusal pending a future larger/streamed adapter
checkpoint design, not a claim that every companion-size review can be written.

## Verification

Twenty focused host cases compile the production state handler, F15 account,
F17 owner and real journal/publication code. Cases include remote before/after
commit crashes and timeouts, checkpoint restart/dedup, every local publication
operation under eager/delayed persistence, account/source/login isolation,
open-book deferral, stale tokens/manual status, known/unknown/cleared rating and
review state, malformed/truncated/oversize data, raw unknown status history flags, the completed F18b stats wrapper and failed writeback.

Each simulator profile runs eleven scenarios and 34 boots against an independent
SD-backed fake server: normal/dedup, before/after commit crash, before/after commit
timeout, open-book deferral, native-publication crash and four owner checkpoint
cuts. Seven abrupt exits are deliberate; no failed scenario is retried. Real HAL
publication stores both remote and native receipts. Reports distinguish bounded
allocation capacity from unavailable ESP32 heap/largest-block/stack-watermark
metrics. All three hardware images retain the otherwise dormant handler for
physical image, static-section and map reserve measurement.

Maintainer hardware verification after activation is authorized: on X4 Pro,
X4 Classic and X3/C3 X4, use a synthetic account/book, close/reopen and restart
around fake state commits. Expect one committed exchange, no writeback while
open, explicit rating clears only with proven history, and a newer manual
status/Undo token to survive a late reply. Check read/turn/close/resume and native
stats remain unchanged; inspect internal free/largest heap and sync-worker stack
watermarks. No EPUB cache reset is needed. Agents must not access devices or
serial ports; these tests supply no device acceptance or release authorization.
