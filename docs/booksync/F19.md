# F19: position policy and durable consent state

Semantic reference: BookSync integration commit
`6a101edfa29dfb583decc176504284e5cc0412b2`, companion `PositionPolicy.kt` and
`SyncOwner.kt:128–209`, `docs/design/position-sync.md` section 3, and Home design's
existing reading-gate exception. The exact shared recorded fixture is copied to
`test/fixtures/position/cases.json`; the host build generates tests for every
`decide`, `apply` and `push` row. This is an independent C++ implementation, not
an extraction of the older firmware orchestration or plugin Lua.

The ordered automatic rules match Android: override first unless superseded;
no remote; same-place; reset; finished reread hold/release; remote ahead; local
ahead with unchanged remote; percent-only fallback; unchanged local marker;
then the 600-second skew rule. A released reread retains an explicit presence
flag, so remote timestamp zero remains distinct from no release. No declines a remote timestamp, including reset
redating while that reset remains active. It does not create an override. A new
remote timestamp is decided afresh; reading beyond it can still push. A queued
explicit override retains the chosen raw locator and capture time, clears the
decline and bypasses the behind-hold once. A newer deliberate remote movement
drops it. Confirmed sends invalidate answer tokens; older captures cannot undo
an already-sent override. Custom Keep/Ask/Follow direction semantics also match
the companion, including persisted first-comparison state (reset by `opened`), Ask suppression at a scheduled pause and cached silent
Follow only before render. After render both moving strategies use consent.

`PositionStore` is worker-only and uses F06 atomic publication. `PositionSync`
consumes the neutral F18e progress projection; it owns no transport and cannot
create a second writer. F18e evidence remains the live-integration seam:

- Map the normalized reply into a `PositionValue`, retaining raw locator bytes,
  source format/version, label, percentage presence and timestamp. Detect reset
  and redating in the adapter/mapping seam; never infer them from a label here.
- Load the exact F08 account/book/edition/revision binding. Record values borrow
  their bytes; reload from the store before reusing a transient reply/capture
  workspace for another operation. `observe` rejects
  foreign evidence and idempotently saves unchanged replies. Native geometry
  must map the remote and marker against that same source, never a different
  edition or percentage synthesized into a native locator.
- `evaluate` takes the matching remote token and native mapped geometry. It
  saves allow-push, override-drop, reread and wake-pending state before publishing
  its decision. `mayDeliver` enforces the behind-hold; use the stored override's
  original percentage/raw/capture time when Override is chosen. Custom directions exempt the behind-hold; only Custom close/sleep/suspend
  captures bypass a saved hold. A lifecycle capture must be re-evaluated against the current remote before delivery.
- Only the existing F17 worker may feed an authorized intent to F18e. Unknown
  remote outcomes retain the override and journal attempt until F18e reconciles;
  call `sent` only with confirmed original commit evidence, never a guess.
- `answer` returning Saved for Yes permits the reader to use its preserved raw
  source locator, after rechecking the current F15 epoch and F12 document/path/
  invocation/mode. It never navigates itself. Stale/duplicate answers and storage
  failures never authorize movement. Equal observations and confirmed-send replays
  re-publish the same bytes without changing tokens/watermarks, so a file that
  became visible before a failed final directory barrier is made durable before
  F17 can acknowledge the phase. On any failed save, reload and reconstruct
  the policy session before further work; a failed session cannot deliver.

No live adapter, UI intent, screen, reader navigation or network activation is
introduced. The existing Library-only UI boundary remains intact; F41 presentation
will consume public immutable Library values/intents. Only the already-approved
position prompt is permitted: position-sync section 3.2's Yes/No question,
including the backward-move wording. No choice screen or additional presentation
is supplied here. The F12 `PositionPresentation` gate is unchanged: the same
live document/path/run/mode and account epoch may claim one draw after its caller
times out. Closing, changing books, A→B→A, a new invocation or a mode change
retires that claim; sleep/hidden views do not paint. Sleep decisions persist
for a new wake-local invocation, and close decisions do not move the reader.

Bounds: no policy heap allocations, tasks or new steady-state globals. The caller
reuses at most 16 KiB read workspace on its existing worker; writes stream borrowed
views with an 8-byte encoder and a 128-byte validation chunk. `PositionRecord`
contains views and scalar metadata, not three locator arrays. Do not place the
read workspace on a task stack. Scope tokens retain F08’s full 128-byte bound. Files are explicitly closed; no simultaneous
readers of the same path are required. The new `BPS1` format is documented in
`docs/file-formats.md`; EPUB caches and native progress files are unchanged.
The dormant full policy/store are force-linked for all physical reserve checks.

Host coverage includes all shared cases plus stale/duplicate tokens, reset
decline redating, edition/account conflicts, raw unknown/binary locators,
override ordering, caller timeout and F12 one-draw consent, sleep/wake,
corruption/unknown versions, token exhaustion, failed saves, and every publication
cut. Each simulator profile uses real HAL storage and synthetic replies over
five independent restart sequences (14 boots): late consent/decline, stale token
and lifetime, sleep/wake, offline override/restart and account conflict. These
are deliberate restarts, never retries of a failing scenario. Native heap/largest
block/stack watermarks cannot represent ESP32 acceptance and are reported unknown.

Maintainer hardware verification after live integration: on X4 Pro, Classic and
X3/C3 X4, open a synthetic same-edition book, read locally, and delay a remote
reply beyond caller timeout. Expect one approved Yes/No prompt while that exact
book/run remains live. No keeps the native page across restart and does not push
behind; a newer remote may ask again. Switching book/account/mode or closing
before the reply must not repaint or navigate. Test an offline chosen override,
a newer remote override, reset decline/redating, finished reread release, sleep
then wake and interrupted policy publication. Confirm native turn/close/reopen
anchors remain unchanged and inspect internal heap/largest block/worker stack
watermarks, especially C3. No EPUB cache reset is needed. Agents do not access
devices or serial ports.
