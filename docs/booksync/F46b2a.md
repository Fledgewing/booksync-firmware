# F46b2a: native state and progress application

This component supplies concrete F18d/F18e evidence behind the private adapter.
It follows F46b1's bound native observations. The revised PLAN splits remaining
native application into state/progress, annotations and retained TLS trust.
Real phase transport follows in F46c1; the sole worker and default Library are
connected in F46c2. No automatic sync, task, screen or reader movement is added here.

`SourceFile` verifies the complete file SHA-256 against an independently issued
F08 binding. Neither a path nor a partial protocol digest supplies identity.
Its caller proves held reader/writer exclusion and admission throughout each
transaction. It checks that proof before opening, between 256-byte reads and
after closing; changed identities, paths, bytes, lengths or permission fail.
Account/source scopes and the F15 owner/epoch are independently rechecked by
`NativeCaptureGate`, including when process login numbers are reused.

## Immutable capture and application

Before any lifecycle attempt, private `ProgressCapture` and `NativeStateStore`
freeze the full entry tuple: opaque server/account, delivery ID, document token,
original native open ID, BSO2 payload and exact source. Create-only publication
cannot recapture newer native values on restart. Unknown/truncated formats and
existing conflicting authority stay untouched. Unknown raw native locators remain
binary bytes in the frozen capture, rather than becoming a percentage anchor.

`NativeProgress` defaults to fetch. Only a preserved supported lossless protocol
locator plus a frozen explicit F19 delivery intent and current saved F19 permission
authorize a new outgoing operation. A newer override cannot be erased by an older
ordinary capture. The override origin survives capture and `PositionSync::sent`
retains its watermark. A pending BSP1 result permits local recovery without
authorizing another PUT. Local marker equality provides publication deduplication
only; it is never evidence of a remote commit.

Progress replies publish through `PositionSync`, preserving raw locators, fraction
presence, timestamp, label, reset and browser provenance. Exact raw same-place
redating is normalized here; more complex geometry remains with the mapper/policy
owner. No position store operation navigates or saves native reader progress.
BPS2 adds browser provenance while retaining BPS1 reads.

`NativeStateStore` is a new scoped private store, not a legacy queue importer.
It keeps local values separate from remote-known history and preserves full status,
review and date bytes within their declared bounds. Unknown history flags replace
stale certainty without clearing native values. Known zero rating and absent review
are explicit clears; a present empty review is distinct from absence.

`NativeState` freezes local values and known history. Application rechecks closed
source/account, current native user-status token and pending manual intent.
Background publication does not advance the native user token or clear a pending
manual intent. The local intent owner must advance that token before a new manual
status can race background delivery. A masked staged status still stores the
original remote-known history. Ratings/reviews apply only when known; unrelated
local fields survive. Every failed publication remains pending for the phase owner.

The existing F18 journal checkpoint bound remains 1024 bytes in this component.
An oversized F18d/F18e reply cannot be truncated or acknowledged; the existing
phase retains uncertainty. Full captures/reviews in these stores do not claim to
expand that separate transport/checkpoint capacity.

## Bounds and recovery

The source guard is at most 2 KiB and reuses a fallible digest object of at most
256 bytes. Progress uses disjoint 8 KiB capture and 16 KiB F19 projection scratch.
State uses disjoint 24 KiB capture/current scratch; each codec object is at most
1536 bytes and each provider at most 2 KiB. The future worker allocates optional
workspaces once per admitted phase, reuses them, and releases them before reading.
No raw payload array is local to a task frame; compiler frame gates enforce 512
bytes for the new production methods. This is distinct from device stack high-water.

The linker-only budget root retains construction, concrete vtables and durable
application in physical images without a startup caller. Simulator fixture arrays
are simulator-only and provide no ESP32 heap evidence. No PSRAM dependency or new
framebuffer exists.

Formats are documented in `docs/file-formats.md`. The owned read-only inspector
accepts copied BPG1, BNS1, BPS1 and BPS2 records before live activation:

```
python3 src/booksync/server/bookorbit/recovery.py copied-record.bin
```

It validates complete framing, integrity, field bounds and binding structure;
it prints format/size metadata only and performs no repair, migration, deletion,
acknowledgement or network work. Record validity is separate from live source and
account authority. Unknown versions return failure while retaining original bytes.

## Verification and later hardware acceptance

Host coverage compiles the concrete providers, F15 account, F19 store/policy and
real journal/publication primitives. It includes every publication cut with eager
and delayed persistence, full raw reviews, independent source/document/account
checks, token rollback, workspace/scope aliasing, known clears, manual status,
override replay, browser provenance and failure/reading transitions during hashing.
The recovery reader has independent bounded vectors and inspects actual simulator
publications. Each profile runs separate capture/apply/restart processes, account
switch, wrong scope, changed source and deliberate abrupt local publication cuts.
Native progress, retained backups and unknown legacy bytes stay unchanged.

After F46c2, maintainers should check Pro, Classic and X3: open/turn/close/restart
an EPUB, fetch a remote place without native movement, retain an unknown locator,
change accounts/source bytes and exercise a pending manual finish against a late
state reply. Inspect internal free/largest heap and worker stack high-water;
native simulator/compiler measurements do not qualify those. No EPUB cache reset
is needed. This component accesses no device or serial port.
