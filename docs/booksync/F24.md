# F24 copy replacement

The worker accepts a unique scoped F08/F18 match for the exact path and canonical
book/edition. A current revision is skipped. Missing, conflicting or unverified
identities are skipped; there is no title/path-only fallback. A new selection
must carry full-file SHA-256 or an opaque adapter verification proof. Unknown
proofs never become canonical revisions: F23 computes SHA-256 after verification.

`CopyJobs` owns the existing F23 worker, admission and one durable pending job.
It creates no task, timer, payload allocation, second writer or UI. Schedule one
copy at a time through the sync owner during non-reading online opportunities.
The caller retains discoveries that cannot be admitted; an admitted job survives
restart in the F23 journal and resumes explicitly. Discovery/refresh triggers and
the setting/control remain outside this service slice. Never invoke replacement
from paint. Library remains the only UI boundary.

A replacement requires the `replacementClosed` port, even when foreground
network admission is available. The owner checks the target's complete document
lifetime, including Home/panels above a loaded book, and excludes reader opens
through publication. A missing callback fails closed. Late book entry pauses the
transfer; resume and filename recovery also respect that lifetime.
The old full-file revision is verified before transfer. Staging stays at the
exact `.tmp` sibling until its new proof and framing are verified. Publication
retains the old EPUB at `.bak` until verified identity linking succeeds, then
retires that exact verified backup with a directory barrier. Cleanup failures
remain pending, so advancing to another book cannot orphan an owned rollback
file or block a later update. A failed staging-to-current rename restores the
old filename before reporting failure where storage permits; otherwise recovery
must restore it before Library exposes the path for opening. This local recovery
checks reading/job exclusion (including prepared leases) and SHA-256 without
activating networking or parking the display; it works offline. Filesystem
recovery does not mark an updated identity linked: its normal verified link
remains required before reporting update completion. A verified new file
with a failed identity link stays pending and retries the idempotent link without
network or another download. Only new bytes can produce successful completion.
Only a journal-owned, verified backup can be retired.
Unrelated staging/backup files and externally changed EPUBs are retained.

CrossInk's native cache, bookmark and clipping identifiers are path based.
Keeping the path and canonical book/edition preserves native progress, visible
text/source anchors, highlights, bookmarks, reader settings, statistics and
unknown state without translating or rewriting them. Reader behavior and cache
formats are unchanged. The BSDL journal is v3; v2 first-acquisition journals remain
readable. See `docs/file-formats.md` for the exact schema/recovery rules.

Host tests compile production copy/download/publication code, including current,
old and ambiguous evidence, edition/account conflicts, missing proofs, wrong
bytes, full/read-only cards, identity-link restart, repeated updates, v2 journal
recovery, and cuts at every storage boundary in both eager and barrier-only
persistence models. Recovery itself is cut at every boundary and refused while
reading. Simulator tests use real old/new EPUB ZIPs with identical text and
changed metadata, preserve the native fixture corpus byte for byte, cut every
publication checkpoint without destructors, and run the retained native reader
source-anchor/reflow/close/reopen scenario on the updated EPUB in all three profiles.

Maintainer-only hardware verification: on X4 Pro, X4 Classic and X3/C3 X4, save a
passage, highlight, bookmark and book-specific reader setting in an EPUB. Close
it, run a same-edition metadata update through the copy worker, then reopen at
the same passage and check all annotations/settings/stats. Repeat with full and
read-only cards, a wrong proof, and loss of power between old-to-backup and
staging-to-current renames. Recovery must expose a complete old or new EPUB at
the original path; failures must not link an unverified revision. Attempt an
update while the book or an in-book panel is open: no transfer, replacement or
presentation may occur. Inspect internal free/largest heap and task high-water
marks; native simulator RSS is not device acceptance. No cache reset is required
for these metadata-only same-edition updates. This slice never touches a device
or serial port and does not enable live scheduling or a new screen.
