# F18b: captured page history and stats delivery

The coordinator authorized an F09 capture extension on 27 November 2026 so
firmware can use the companion stats protocol without inventing page history.
This independently implemented phase follows the `stats` branch of BookSync's
`android/companion/app/src/main/java/net/fledgewing/orbitcompanion/server/bookorbit/BookOrbitSync.kt`
at `7b3220fe6920180ffbbc34b9307508db71b6c893`.

Native EPUB/XTC accepted intervals supply duration and clock boundaries; no
second timer, idle policy, counter, reader setting or native save result changes.
The start hook records native spine/page/page-count coordinates in fixed RAM;
EPUB whole-book fraction and optional source offset resolve in the existing F09
main-loop observation once per accepted interval, not on every loop. No progress fallback or file read is added to paint.
TXT has no native timer and invents no stats. Unknown/changed clocks, missing
coordinates or an overflowing eight-row queue produce an explicit coverage gap.

`PageJournal` is a separate, logical append-only history under `/.booksync/pages`.
Its 64-row segments follow F07's version/checksum/refuse-unknown/non-eviction rules
and F06's staging/flush/validate/backup/rename barriers. It does not expand the
64-entry lifecycle queue or rewrite an entire history per turn. Only the active
segment is republished; completed segments remain immutable. It keeps no open
file between operations and closes its source before publication validation.

There are at most 50,000 event rows plus one permanently reserved capacity-gap
row. When full, old rows remain intact and capture refuses further events;
there is no silent oldest-first eviction. The capacity gap is open-ended and
requires explicit later recovery/retention policy. No automatic pruning ships.
Current files use 3,212,512 bytes at 50k rows; conservative current/backup/staging
storage remains below 6.5 MB. The fixed queue survives transient write failures
in RAM; a successful flush acknowledges only complete publication. As with F09,
a power cut can lose unflushed intervals; an unclosed F09 open remains incomplete
source evidence, never proof of complete coverage. Full/read-only SD failures
leave native saves independent and log the retained capture/coverage problem.
No software can promise a new durable marker when the card rejects every write.

F18b runs only under F17's borrowed writer token, after a valid F18a match. Its
private evidence provider must bind the exact F09 open, frozen source-row range,
capture cutoff and F08 revision to the current adapter/account and F15 sync
connector. The default adapter remains offline pending import/activation proof.
No source rebinding, account-password fallback, OPDS login, native upload writer,
new session endpoint or outgoing activation is added.

The private transport issues `/koreader/plugin/page-stats` with the companion's
device envelope and sync authentication. Whole-book fractions become `page` /
`totalPages`; accepted duration is clamped to 0–86400 seconds. Optional explicit
`bookFileId` comes only from F18a. The server owns session derivation, reading time
and daily totals. Native cumulative totals and timed-session records are never
uploaded again as additive time. Ambiguous metadata follows the companion's
no-upload behavior; missing evidence, coverage gaps, malformed replies and
unmatched files stay pending.

A batch contains at most 32 rows, below the companion's 256-row bound. A stable
physical source-row cursor replaces SQLite's `(startTime,page,id_book)` cursor:
every frozen row is considered exactly once even across equal timestamps,
clock reversals and intervening books. Records after the capture cutoff are not
sent. The row range/cutoff is immutable across retries. The server's verified
`(account,file,device,page,startTime)` dedup key makes exact batch replay safe;
timeout after commit never creates a speculative acknowledgment. Reply hash,
accepted/duplicate counts and watermark must cover the full request.

F17's new `Checkpointed` result publishes a confirmed partial cursor without
acknowledging Stats or clearing its durable attempt. Only the final batch marks
Stats complete. Failed/uncertain checkpoints repeat the identical batch. `BST1`
wraps the original F18a bytes intact, including the raw native capture; the match decoder transparently unwraps that known envelope for later phases.
Unknown or nested stats envelopes remain unresolved.

Production capture/history/phase code introduces no explicit heap allocation; existing HAL file wrappers retain their fallible allocation behavior. Each reader bridge owns
one fixed eight-event queue; the worker supplies a reusable 32-event batch and
1024-byte checkpoint output alongside F17's existing scratch. Segment reads and
publication use fixed 64-byte rows; recovery streams at most 782 segments.
On the native ABI, a PageEvent is 56 bytes, PageCapture is 520 bytes, PageJournal is 416 bytes, and the reusable 32-event wire batch is 768 bytes. These are fixed object bounds, not ESP32 heap measurements. The phase keeps fixed identity/evidence values on its worker stack; the larger batch and checkpoint output are caller-owned. There is no history-sized task stack, vector or JSON tree.

Host tests compile production capture, page history, phase, Account/Auth, F17,
F07 and F06 with synthetic storage/transport. They cut every local publication
operation with eager/delayed metadata, cut before/after remote commit, test
uncertain responses/restart/dedup, scope/revision/epoch isolation, malformed
replies, immutable snapshots, queue/cap gaps, corrupt/unknown files and 50k history.
All three simulator profiles require the durable fake-server scenario including
50k rows, power cuts, timeouts and multiple restarts. Reports explicitly leave
ESP32 free internal heap, largest block and task stack high-water unavailable;
native host memory cannot substitute for hardware acceptance.

Maintainer verification after activation: on X4 Pro, X4 Classic and X3/C3 X4,
read a synthetic EPUB through qualifying dwell, rapid turns, pause/resume and
close/reopen. Compare anchors, native counters and input behavior with the base.
Use a fake sync account, interrupt before/after commit and confirm one remote
page tuple and one derived contribution to sessions/time/day totals. Exercise
full/read-only storage and clock corrections; gaps must remain visible in source
evidence, never successful zero history. Inspect internal heap/largest block and
worker stack high-water (plus PSRAM on S3). No EPUB cache reset is needed.
Agents accessed no devices or serial ports. This is no release acceptance.
