# F37a: approved service picker and account presentation seam

Approved scene: BookSync `docs/design/booksync-firmware/mockups.html#server-choice`
(B5, approved via #203). Touch selects either row then Continue; buttons move
through service, saved books, Continue and Later. Back/Later close without an
intent. Continue sends an opaque service key with the captured account epoch.
Saved books uses key zero and does not sign out or remove retained credentials.
Selection is session-only and is not an authentication result.

`ui/account/ServiceChoice` consumes Library only. `system/AccountScreen` adapts
its cached values to existing renderer/input primitives and ActivityManager
ownership. `showServiceChoice` is an explicit setup/settings navigation seam;
there is no unsolicited entry and the existing Home/reader routes are unchanged.
The future B5 first-run/settings host must call it after a user action. A device link anchor retains this approved picker so the size gate includes its
full renderer and controller even before navigation activation. The
screen is therefore not currently reachable from the normal Home navigation.

The public AccountView is at most 64 bytes; ServiceChoice is at most 96 bytes.
It contains status/capability booleans, an opaque key, epoch and bounded service
label. No user identity, address, secret, raw response or private service pointer
is exposed. Bootstrap publishes F15's normalized status after F29 activation and retained-login retirement;
paint reads only the controller's cached values. No new task, file, durable store,
credential buffer or framebuffer is allocated. ActivityManager owns the single
fallible screen allocation; the bounded model stays inside that activity.

Closed controllers stop reading Library and cannot schedule another repaint.
The render callback also checks liveness under RenderLock before touching pixels.
Same-owner epoch changes (including A → B → A) close the old presentation.
Dispatch checks the epoch again, and the Library rejects stale selections.
The picker accepts local selection only: it never invokes a network writer.

## NEEDS APPROVAL and unavailable live authentication

BookSync [#224](https://github.com/Fledgewing/Orbify/pull/224) adds eleven explicit
account, capability, manual and phone sign-in scenes with all three profiles,
marked NEEDS APPROVAL. Merging that documentation is not approval. None of those
new scenes is implemented here. Q1 retains QR, readable live link and manual
Check when the library phone sign-in surface is subsequently approved and backed
by a live adapter. Pro entry keyboards must dock at the bottom.

F15's current default adapter supports offline restoration of independent logins
but advertises no live web-account authentication. This slice does not fabricate
successful account or phone sign-in. F37b/F37c, live auth/phone transport, the
remaining account presentations and their navigation are deferred.

## Verification

Eight host cases cover opaque selection/epoch forwarding, saved books and Later,
closed-view silence, same-owner epoch retirement, owner changes, unavailable
selection, unsupported service and bounded labels/capability absence. Each of the
three simulator profiles runs `account_surface.py` once with a synthetic Library,
five captures, successful offline selection, button/touch Back, account-switch closure and no
Library read/intent during paint. Existing F15 account/secret-erasure and F12
delivery tests remain in the full host/simulator gates.

Run `python3 tools/ci/host.py`; build all three hardware and simulator profiles;
run `python3 test/simulator/account_surface.py <simulator-profile>` and the normal
`boot.py` gates. Hardware size reports use the unchanged 6,553,600-byte slot and
131,072-byte minimum reserve. Simulator metrics are host-only evidence.

Maintainer-only hardware verification, after approved setup navigation connects
the seam: on X4 Pro tap service/saved-books then Continue; on X4 Classic and
X3/C3 use Previous/Next/Select, Back and Later. Expect focus and selection to
stay distinct, saved books to remain usable, and no authentication-success claim.
Close the picker before a simulated account update and confirm it never reopens
or repaints over the reader. Reopen a local EPUB and confirm native position and
page turns are unchanged. No cache-format change or cache reset is needed.
Agents do not flash devices or open serial ports.
