# F31 — unified version, bridge and source identity

Follows BookSync `docs/design/unified-version.md`, `release-versions.md` and
`update-channels.md` on the integration repo's `feature/0.12`. No feed lookup,
release publication, device access, installation or screen change is added.

`system/Version.*` separates BookSync precedence from the immutable source tag,
CrossInk base and firmware source commit. Test < preview.N < rc.N < stable;
numeric identifiers are compared numerically, and unified build metadata never
changes precedence. Invalid nonempty product identities fail closed. Empty
product identities retain the legacy numeric comparator, including the fork
counter, sanitized installed labels and RC suffixes. Equal-product bridge rebuilds
use the fourth numeric source counter; unified builds ignore the CrossInk base.

`system/UpdatePick.*` matches exact device asset boundaries for `firmware-x4-pro`,
`firmware-x4-classic` and `firmware-x3-x4`. Stable/RC/Preview eligibility uses
BookSync identity, independently of GitHub's prerelease flag. Test identities and
missing/invalid product fields are never eligible. Retained legacy feed heads are
for old readers; those old readers ignore the product alias and can still choose
a higher numeric bridge. Stable-channel bridge reachability remains necessary.
The fixture models `2.0.0.373 → 2.0.0.801+bookorbit.1 → 0.12.0` for each stem.
The final installed-version check uses the same comparator as selection, so
stricter channels never trigger a downgrade. Partial platform previews keep the
older device head when no newer matching asset exists.

Selections are provisional until the complete response, transport, signature and
withdrawal checks pass. Reset both parser and selection before retrying. No tag is
rewritten to its product alias: F30 verification still signs the exact immutable
tag and filename. F32 owns runtime selection/installation admission. Dormant
full-link roots keep both F30 trust and F31 selection in the hardware size gate.

## Build inputs and packaging

`scripts/booksync_version.py` stamps only `Version.cpp`, avoiding source-commit
changes in every translation unit. `BOOKSYNC_VERSION_FILE` points at the integration
repo's `shared/version.json`; this repo owns no independently incremented product
manifest. Without explicit shared inputs, builds are artifact-only
`0.0.0-0.test.1`. With a manifest and no release tag, builds use its numeric core
plus `-0.test.<BOOKSYNC_TEST_RUN>` (default 1). Tests never become feed candidates.

`BOOKSYNC_RELEASE_TAG` is an explicit packaging input, never a publishing action.
Unified packaging requires `xteink-v<shared version>+crossink.2.0.0`. Pre-0.12 bridge
packaging retains its numeric source tag, e.g. `xteink-v2.0.0.801+bookorbit.1`.
Release tags retain exact `+` metadata. Asset filenames follow the existing
producer normalization (`+` becomes `-`) with the three device stems, for example
`firmware-x3-x4-v2.0.0.801-bookorbit.1.bin`.
The CrossInk base is stable 2.0.0 at
`2cdd6117568c8877c3180d5fac8d5b20e55d1ac7`; the separate source commit identifies
the BookSync firmware tree. No submodule pin in the integration repo changes.

Host tests compile production parsing, selection and comparison. Packaging tests
exercise the actual PlatformIO stamping hook with fake build callbacks. Simulator
scenarios feed one-byte, seven-byte and whole-response chunks, interrupt/reset,
select the bridge using old numeric semantics, then select unified stable using
BookSync semantics. All three profiles execute all three asset stems.

The version/picker implementation allocates no heap and uses small scalar parsed
values; it adds no steady-state work or framebuffer. Fixture strings and large
parser/selection objects exist only in the host/simulator scenario. Runtime ESP32
heap, largest-block and task high-water measurements require maintainer hardware
acceptance; native host measurements cannot substitute for those values.

Maintainer verification after F32 wiring: on X4 Pro, X4 Classic and X3/C3 X4 use
synthetic, locally verified candidates to check old → stable bridge → unified
stable, each channel transition and repeated checks after reboot. Expect no test
candidate, downgrade, wrong-device asset or changed reading position. Check exact
source tag in signature diagnostics and product/base/source identity in diagnostics.
No cache format changed; no cache reset is needed. Agents do not perform this test.
