# F15 account worker and authentication boundary

The account worker follows the BookSync Android/plugin model. Account, sync and
acquisition logins are independent, with explicit owner values for each connector.
Successful credential changes and local sign-out advance the delivery epoch even
when the account identity is unchanged. Old queued requests are rejected before
calling the adapter; A → sign-out → A cannot revive presentation tickets.
Failures retain the previous published state. No account operation writes library
records or creates a sync writer token.

`CredentialCapture` is a noncopyable job-owned buffer capped below 2 KiB, including
1024 secret bytes, a 512-byte origin and a 100-byte user value. It uses no heap;
keep it in the owning job rather than a small worker stack. Capture wipes the
caller's mutable secret on success and failure. Completion, rejection and destruction
wipe the captured buffer with volatile writes. No secret is logged or persisted.
The adapter uses only 32 bytes of temporary key storage and 16 digest bytes.

The private adapter derives the legacy sync key from the independently submitted
sync password, or validates/lowercases an explicitly supplied derived key. It never
uses the account password as a sync fallback. Acquisition keeps its own login.
The plugin transport stages credentials until the adapter validates status and a
nonzero neutral owner, then commits or discards the candidate. Sign-out clears account
tokens/candidates and account-derived connector secrets synchronously, even offline.
Explicit user logins retain their independent origins; removeLogin erases each
connector separately. Explicit useAccountLogin changes a connector to account origin,
so later account sign-out revokes it. Account replacement preserves user slots and
replaces account-derived candidates. A future
persistent transport must provide encrypted storage; this slice adds no vault,
plaintext file, token serialization, automatic provisioning or attestation client.

The shipping factory remains offline and advertises no authentication capability
until a plugin transport is integrated. The production adapter normalization and
key handling are exercised with synthetic transports. Unauthorized, forbidden,
unsupported, unavailable, retryable, old-server, malformed-response and
attestation-required states remain typed. Attestation-required replies never
commit a candidate, trigger a fallback, forge evidence or retry another route.

The hardware full-link gate roots the neutral factory, capture and account entry
points and requires the private authentication implementation in ELF symbols. This
measures dormant code before UI integration without enabling transport.

No product presentation is added. F37 owns the approved account screens and their
Library integration. Existing Home/reader behavior, native capture, Tailnet identity,
cache formats, partition map and the single library writer contract remain unchanged.

## Validation

Host cases compile production account/capture/adapter code, including stale and
same-owner epochs, independent connector owners, secret clearing, failed login,
unsupported capabilities, legacy key derivation and malformed/attested responses.
The simulator account scenario runs 17 checks on a fake serial worker in each
profile: independent sync login, account sign-in, permission failure, local sign-out and independent connector removal,
stale input disposal, A → sign-out → A, and zero late presentation repaints.
Synthetic SD roots are disposable and contain no credentials. The scenario never
opens a network connection. Native worker stack/RSS cannot qualify ESP32 memory.

Run `python3 tools/ci/host.py`, build all six required profiles, run
`python3 test/simulator/boot.py <profile>` for each simulator and
`python3 tools/ci/measure.py <device-profile>` for the three hardware images.
No failing scenario is retried to obtain a pass.

Hardware acceptance is maintainer-only: on X4 Pro, X4 Classic and X3/C3 X4,
open a local EPUB, turn pages, return Home and reopen at the saved native position.
Expect unchanged reader controls and no account screen, network request or overlay.
Once the account UI and authorized transport are integrated, additionally verify
independent connector owners, offline sign-out, stale-form rejection, and inspect
internal free/largest heap and worker stack watermark without printing credentials.
No cache reset is required. Agents do not flash devices or access serial ports.
