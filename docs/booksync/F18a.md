# F18a: lifecycle match

BookSync ports only the companion's `match` phase. Its semantic source is
`android/companion/app/src/main/java/net/fledgewing/orbitcompanion/server/bookorbit/BookOrbitSync.kt`
at integration commit `c3cab63a7e9538a8a417a48038b09c24b2859107`, the `phase`
match branch. This independently implemented firmware handler sends the captured
partial digest and optional title/authors/last-open metadata with the current-file
source, selects the reply for that digest, and checkpoints its match evidence.
No companion implementation text or upstream server code is copied.

`LifecycleMatch` is a worker-only phase handler under the concrete adapter. It
requires the borrowed F17 writer token. It neither activates an owner nor writes
the journal. `SyncOwner` exposes an optional bounded confirmed-checkpoint output
and atomically publishes that output with the phase acknowledgement. Toy adapters
that do not return output retain their existing checkpoint behavior.

F15 sync readiness, connector identity, capabilities and the current account epoch
gate delivery. A web/account session or acquisition-only login is insufficient.
An epoch change during transport leaves the attempt uncertain. The evidence
provider must bind the captured document, exact F08 revision, immutable metadata
and partial digest to the same account scope; it must supply a complete bounded
candidate window, never a truncated window that hides conflicts. The handler
resolves the exact path/revision through F08 and rejects canonical/file alias
conflicts. No title-only merge, source identity generation, locator conversion,
reader-path rebinding or global index update occurs here.

Transport is private and injected. The match-check operation resolves existing
hash associations before adding one. An uncertain response is reconciled by that
same scoped operation, with unchanged captured evidence. No speculative remote
acknowledgement or invented protocol idempotency field is used. Missing,
conflicting, malformed and oversized replies remain pending. Identical duplicate
rows are harmless; position-incompatible matches are recorded as incompatible.
Later phases must honor that evidence; this slice implements none of them.
The default adapter remains offline. External replay still requires the later
import/activation proof gate.

The private `BSM1` format is documented in `docs/file-formats.md`. It preserves
the original native checkpoint byte-for-byte; it does not change the journal
version, EPUB caches, native saves or partition map. Insufficient checkpoint
capacity prevents sending. The caller supplies at most 1024 output bytes and
F17's existing 5504-byte journal scratch. The handler creates no heap allocation,
task or steady-state buffer. Candidate windows contain at most eight source rows
and eight canonical aliases. Transport/evidence buffers are caller-owned and
must outlive the synchronous call. No network, index or persistence work runs
from a paint path. Hardware images explicitly retain the dormant handler for
honest reserve measurements.

## Verification

Host tests compile the production handler with real Account/Auth, SyncOwner,
Identity, LifecycleJournal and FilePublish code. They cover before/after remote
commit crashes, before/after commit timeouts, restart and deduplication, epoch
retirement, independent logins, account isolation, ambiguous editions, wrong
revisions, existing alias conflicts, missing/duplicate/oversized/malformed remote
results and checkpoints, capacity refusal, and cuts at every local storage
operation under both eager and delayed metadata persistence.

`test/simulator/lifecycle_match.py` runs eight scenarios per profile through the
production handler, F15 fake authentication, F17 owner, real HAL and an independently
persisted fake server: normal/dedup, before/after remote commit power loss,
before/after remote commit timeouts, and cuts after attempt storage, remote return
and acknowledgement. Each scenario restarts twice; no failing scenario is retried.
Stats stays unavailable and the journal entry remains pending after match.
All three profile boot suites require this scenario. Runtime internal free heap,
largest block and task high-water remain unavailable on the native host; these
are explicitly separate from physical image/static-section/map measurements.

Maintainer hardware verification, after the later activation gate: on X4 Pro,
X4 Classic and X3/C3 X4 use a synthetic account and verified local EPUB. Restart
before/after a fake match commit and confirm one scoped association and a durable
Match acknowledgement, with later phases still pending. Sign out/switch accounts
and confirm old work cannot send with new credentials. An unmatched or ambiguous
edition stays pending. Confirm native read/turn/close/reopen anchors and local
stats remain unchanged and inspect internal heap/largest block and sync-worker
stack high-water. No EPUB cache reset is needed. This slice accesses no device
or serial port and provides no hardware acceptance or release authorization.
