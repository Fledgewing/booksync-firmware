# F35c — Home pages

Audited BookSync design commit `207515633ac6a7456421b8b506c61f639b6ed814`.
Implements the page subset of approved Home revision 16: `prototype.html`
`editHead`, `editFoot`, `pageAdd`, `renameView` and `pageMove`; gallery scenes
`x4pro-edit`, `x4pro-renamed-page`, `x4c-edit` and `x4c-renamed-page`.
The naming keyboard follows the maintainer's bottom-docked touch ruling in
firmware `SCREENS.md` and the slice instruction. Classic keeps the approved
preset-name list and Select-to-cycle field. Page deletion is outside this slice.
X3 [approval #213](https://github.com/Fledgewing/Orbify/pull/213) covers add/remove/reset only: page editing stays disabled and
no X3 page screen is added. No new X3 presentation is needed for this slice.

UI uses only Library values and intents. Create inserts an empty page after the
current page; rename trims outer spaces, bounds the UTF-8 byte buffer to 80,
escapes JSON quotes/backslashes and sets `named: true`; the first widget supplies
a localized name for an untouched Page N, without replacing manual names; reorder moves complete
source page spans. Unknown fields, widgets, settings and class overrides survive.
Every operation checks the captured revision and validates all class projections
before the existing LayoutStore/FilePublish atomic save. Source readers close
before rename. Full/read-only cards and interrupted publication retain a complete
old or new revision. No schema, reader, EPUB cache or sync-owner change is made.
The worker selects the created/moved page only after a successful save.
Empty pages retain normal touch/button paging after leaving the editor; Confirm
on an empty page cannot open an undisplayed book.

The existing 4 KiB streaming workspace is reused. Its new page-span array is
192 bytes on the worker stack; this bounded array avoids a JSON-tree allocation.
Naming retains an 81-byte buffer in the editor. Pro reuses one fixed SDK keyboard
hit table (compile-time cap 2 KiB) in the existing fallible activity allocation; there is no per-frame or per-key heap
allocation, task or second framebuffer. Native component sizes are 1,832 bytes
for the hit table, 32 for keyboard entry, 344 for the editor and 156 for an edit
intent. Editor and keyboard-entry caps are 384/32 bytes. Retaining these bounded
values in the activity avoids putting them on the task stack or allocating them
for every key. The reusable worker workspace remains 3,864 bytes and its native
requested allocation is 24,616 bytes; native figures are separate from hardware
acceptance. The keyboard occupies the usable bottom,
with field/actions above it in portrait and landscape. Native RSS is simulator
process evidence, not ESP32 internal heap, largest-block or task-watermark proof.

Host tests cover create/insertion order, name escaping/blank/control/length bounds,
manual-name retention, 16-page capacity, both reorder directions, large opaque
source spans, stale revisions, canceled naming, retired replies, and every atomic
publication cut including full/read-only storage. `pages.py` adds actual mapped
input and synthetic HAL persistence/restart scenes to all three simulator suites.
X3 proves the entry stays disabled and page edit requests are rejected.

Maintainer hardware verification remains pending: on X4 Pro open Edit Home,
create a page, name it using the bottom keyboard, cancel a name, save a name,
move the page left/right and reboot. Repeat with Classic Previous/Next, Select,
the preset list and Back. Expect the same named page after reorder/restart,
visible focus, no write on canceled naming, and retained layout after storage
failure. Change a layout while naming to verify stale-edit rejection. Confirm
X3 has no page editor and each reader resumes its native EPUB position unchanged.
Check portrait/landscape and internal free/largest heap and task stack high-water;
S3 PSRAM is separate. No cache reset is needed. Devices and serial ports were
not used; no release or submodule-pin update is part of this slice.
