# F35b — Home movement, resize and focus

The approved revision-16 presentation was audited at BookSync integration
commit `46e83662b372822a0228cb7b9c7417157f87094f`. It is BookSync Home `DESIGN-NOTES.md`
§5, `prototype.html` `planMove` / `nextSize` / `editFoot`, and the gallery's
`x4pro-edit`, `x4c-edit`, `x4c-edit-carry` and `x4c-edit-options` scenes.
Pro selects a tile, uses the footer arrows and Size, and drops with Done.
Classic Select grabs/drops, Previous/Next move right/left then down/up at the
edge, More cycles size, and Back cancels the complete carry. More on a focused
unselected tile opens Remove/Done. Focus stays on that tile after drop/cancel,
or on the nearest remaining tile after removal. A changed layout retires an
active stale draft before paint; cancel adopts and clamps to the current page. Page transfers and page editing
remain F35c; blocked movement reports no room without changing geometry.

The X3 editor remains disabled, pending the existing BookSync
[proposal #213](https://github.com/Fledgewing/Orbify/pull/213). This slice needs
no new X3 presentation. X3 receives the same reserved-cell read model, and its
simulator proves the editor cannot be entered and a spatial edit is rejected.

## Contract

UI calls only Library. `previewLayout` returns a bounded value without I/O;
it never persists a carry. One-cell moves use free cells first, then swap the
minimal intersecting band, preserving its order. Every preview validates the
whole projected page, including cells reserved by unknown widget IDs/versions.
Size cycles the approved starter-widget families, trying the current origin
before another free origin. There is no drag animation or per-input allocation.

Drop sends one geometry transaction containing all installed placements with
its source page and revision. The worker resolves those indices against that
revision, checks count, installed size families, positive spans, bounds and
collisions, and validates all three class projections. Only the X4 override
changes; base placement, settings, unknown fields, unknown widgets and other
class overrides retain their exact bytes. Missing override objects are added
without decoding/re-encoding their instance IDs. No schema/cache version changes.

F35a's LayoutStore/FilePublish performs the atomic publication. A stale draft,
failed read/close, full card or read-only card cannot replace the complete prior
layout. Back cancels an unsubmitted carry; Back after acceptance retires the
presentation while the atomic worker finishes. A late result never reopens it.
Readers, captured positions, EPUB caches and sync-writer ownership are unchanged.

## Resources and checks

Native component measurements before F22 query-state integration: the splice
workspace is 3,864 bytes and the Home-worker allocation is 24,528 bytes. The editor object is 256 bytes, including its
232-byte draft. The optimized native planner frame is 128 bytes; UI preview
frames are 512–528 bytes because they pass and return bounded values. These
compiler/native figures do not qualify embedded stack or heap safety.

The worker reuses a compile-time bounded 4 KiB splice workspace in the existing
single Home-worker allocation, capped at 28 KiB. Up to 68 splice descriptors
cover 16 placements with four geometry properties and a revision; instance-ID
insertions stream from the original file. A 1 KiB insertion buffer holds only
new punctuation/numbers. No JSON tree or per-edit payload allocation is added.
The editor retains one bounded HomePage draft; the preview uses bounded value
copies outside paint. This is deliberately larger than the usual 256-byte stack
rule across call frames to avoid heap churn; embedded stack-watermark acceptance
remains required. No recursive planner, task or extra framebuffer is introduced.

The 23 focused host tests cover band swaps, invalid asymmetric bands, free movement, resizing,
reserved cells, repeated edits, carry cancellation, drop/focus, stale drafts,
class isolation, unsupported spans and every publication cut. Existing unknown
field, source-close and storage fault tests remain active. The full host and
boundary suite and all six build profiles are required by CI. `geometry.py`
adds real HAL persistence and touch/button scenarios to the three simulator
boot suites, alongside F35a's add/remove/reset scenarios.

Maintainer hardware verification: on X4 Pro select Continue reading, move it
down past Shelf, resize it, cancel, then repeat and Done. On Classic use Select,
Next, More, Back and Select/drop, and More on an unselected tile for Remove.
Expect no writes before drop, the original geometry after cancel, a complete
layout after reboot, focus on the same tile, and no overlap with unknown widgets.
Test full/read-only SD and stale drafts: expect an error and retained layout.
Confirm X3 has no editor entry and all devices resume an EPUB at its unchanged
native position. Inspect internal free/largest heap and stack high-water marks;
S3 PSRAM does not replace internal RAM evidence. No EPUB cache reset is needed.
No device, serial port or release is used by this slice.
