# F13 local index and Library read model

The main-loop Home worker owns SD enumeration, index publication, retained-window
materialization and read-only native capture projection. The renderer only gets
copied Library values. F13 changes no screen or reader behavior. Home revision 16
and firmware B1–B5 remain later UI slices.

`Library.requestWindow()` and `requestBatch()` coalesce to one pending host
publication. A batch contains at most 16 requests sharing 24 logical rows and
16,384 bytes; the entire allowance is checked before I/O. A single request defaults
to 12 rows. The snapshot stores one shared row array and bounded per-window spans,
so a malformed window can report an error while its sibling remains available.
Summaries read 192 bytes each and paths stay private. File-scan batches contain at
most 16 entries; history cursors contain at most 256 visits (the foreground worker
uses a smaller 16-visit allowance). No catalog or history is resident, including
on X3; there are no per-widget window allocations.

Subscriptions are value cursors: compare with `Library.changed(cursor)`, then adopt
`Library.subscribe()` after consuming the new snapshot. Set `cursor.live=false`
to retire it. A non-reused publication revision also distinguishes checkpoint changes within the
same native journal ID. A non-reused model lifetime prevents old subscriptions from reviving
when Home is recreated. Invalidation changes freshness without reading, presenting,
opening or canceling durable capture. A copied snapshot never changes underneath
its consumer. All mutations use the existing main-loop/RenderLock contract.
Full windows exceed the render task's stack allowance: screen hosts must retain
them in activity-owned storage acquired outside paint, then draw the cached value.
The current shell still draws only its small status snapshot; F13 adds no screen.

The worker's single fallible, at-most-24-KiB allocation is made at Home entry and
released at exit before a reader starts. This avoids task-stack buffers and leaves
no index allocation resident during reading. HAL directory wrappers are bounded
by eight open directories plus one entry and the streamed data writer. Paths are bounded to 1024 bytes, names
255 bytes and display titles 95 bytes (UTF-8-safe truncation is explicit);
unsupported path/depth bounds and storage/iteration
errors stop publication and retain the prior generation. A scan is manual Refresh
or the first cold Home entry; warm Home uses the saved generation. Filesystem
changes require a Refresh; worker-produced changes invalidate the retained window.

F08 identities remain unknown until independently supplied. F09 capture continues
to own durable native observations; its successful checkpoints invalidate the
read model. Projection streams those observations and picks the latest native
open for each visible exact path with matching source evidence. Bound editions
reject unbound or different-edition observations; unbound native observations
remain local display evidence. It preserves observed native counters rather
than adding overlapping sessions. Personal-provider precedence and rich historical
aggregates remain F39. F12 presentation remains quiet: polling publication never
requests a repaint or navigation. Indexed opens require a live generation key and
resolve only in the worker before using the existing reader navigation.

Verification uses a synthetic 10k-file SD, cold and warm scans, 50k streamed visits
(197 cursor windows), interruption, stale keys, card errors and publication cuts.
Host elapsed times are diagnostic; simulator memory is not hardware acceptance.

Maintainer hardware check (no agent device access): on X3/C3, X4 Classic and X4
Pro, open Home with a synthetic 10k-book card, let the cold worker finish, then
restart and confirm warm entry reads the saved window. Open/read/Back must retain
native anchors and saves. Interrupt a Refresh and confirm restart keeps the prior
complete generation. Observe the bounded worker allocation log and measure internal
heap, largest block and task high-water before Home, while scanning and after reader
entry; index memory must be released before reading. No EPUB cache reset is needed.
