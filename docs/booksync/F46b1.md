# F46b1: immutable native match and statistics evidence

A worker may prepare an independently issued source identity, verified full-file
revision, retained opaque account scope and private protocol proof before a
native open. `Capture::open` can then preserve those bytes in BSO2. BSC2 freezes
the native page interval and original open ID when closing; delivery-journal
renumbering cannot attach another book's page observations. Unknown/unbound BSO1
history stays local. No current path or partial protocol digest supplies identity.

`SourceAuthority` publishes independently entropy-issued book and edition UUIDs
once using create-only FilePublish. Existing authority, including corrupt or
unknown bytes, prevents reissuance. Validation is current-only; backup rollback
cannot change a published identity. The caller owns the lookup index and supplies
exact verified revision, opaque scope and a production entropy provider.

Each provider freezes its construction-time F15 owner/epoch and rejects any
account transition, even if a fake reuses the process owner or routing strings.

The private `NativeEvidence` implements F18 match/statistics evidence against the
immutable capture. It requires the retained scope to agree with both payload and
delivery routing. Match receives complete captured metadata and exact revision;
statistics receive the closed frozen page interval, timestamp and native open ID.
Live samples, old unbound observations, unknown proof versions and unavailable
page history do not become successful delivery evidence.

This review unit supplies the durable codecs and concrete providers. The existing
reader bridge continues its local observations. Pre-open worker preparation,
retained scope selection and projection into the sole sync owner's delivery
journal are wired in F46c2. No automatic networking or reader movement is added.
F46b2 supplies annotation/state/progress application; F46c1 supplies real phase
transports. F19 and F20 are merged and will plug into those later units.

The 2512-byte maximum bound-open buffer is a fallible cold allocation released
at transaction end, rather than permanent C3 DRAM or a large task-stack buffer.
The source authority owns a reused 334-byte codec workspace. Native samples add
24 bytes for the frozen interval, time and original open ID. No framebuffer,
thread, PSRAM dependency, native store rewrite or legacy queue retirement is added.

A linker-only budget root retains these dormant provider/authority methods in
physical images before automatic scheduling, so the size reports include them.
It has no startup caller.

Host tests cover account/revision isolation and epoch transitions, independent IDs, current-only
corruption handling, entropy failure, malformed/truncated records, immutable
closure, delivery renumbering and every publication cut. The simulator writes
actual SD files then checks source and account evidence in a separate process;
all three profiles run this through the existing boot suite.

For later hardware acceptance, on Pro, Classic and X3, open a current EPUB, turn
pages, close it and restart. Expect native reading/resume behavior to be unchanged
and local history retained. After F46c2, verify that only newly bound observations
from the matching account are delivered and that reused paths, unknown time or
changed source bytes remain pending/unbound. Inspect internal free/largest heap
and task high-water marks. No EPUB cache reset is needed. No device was accessed.
