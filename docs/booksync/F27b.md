# F27b: read-only reading annotation import

`src/booksync/import/ReadingAnnotations.*` stages evidence only. F29 owns inventory
walking, account/edition resolution, activation and first external replay. There
is no bootstrap call, Library/UI surface, transport, journal acknowledgment or
native annotation-store rewrite in this slice. Reader behavior stays unchanged.

The format references are the F03 inventory pinned to legacy commit
`87e2e1984481e8a3d996f12b34b50a383f9013b8`, its `docs/file-formats.md`
(clipping v1–7, BOA1, BOB1/2, BOD1/2) and `src/BookmarkStore.cpp`
(bookmark v2–5). Bookmark v1 and unknown future formats stay unsupported.

The caller supplies a bounded read-only input and a format discriminator, never
an inferred format from a filename alone. Inspection validates before exposing
record byte spans. Native selection ranges, layout signatures, snippets, upload
flags, scope-prefixed and unscoped tombstones, xpointer bytes and identity epochs
remain in their original encoding. Tombstones are not filtered or acknowledged.
BOB1 with a nonzero exchange watermark remains marked as requiring recovery;
BOB2 does not erase that evidence from separately archived BOB1 files. Watermark
zero, exchanged-empty one and later timestamps remain distinct. Download headers
hold a server CRC, not an annotation watermark. BOD2 offsets, lengths and FNV path
hashes are checked; numeric IDs and paths are raw identity evidence for F27d,
never a canonical book/edition match. No title/path-only join is made.

Each primary, backup and revision gets its own caller-reserved archive path and
opaque provenance (including inventory source, account epoch and backup role).
No "best" source replaces another. Unknown, truncated, over-budget or corrupt
sources remain untouched and unresolved. The import API opens sources only with
`O_RDONLY`, explicitly closes handles and never calls legacy recovery routines.
The caller must exclude concurrent source mutation and serialize archive writers.
Archive destinations are restricted to `/.booksync/import/annotations/`, outside
legacy storage. Use distinct canonical paths there; filesystem aliases
such as FAT short names must not name legacy sources. Empty/dot segments,
trailing dots/spaces and ASCII case aliases are rejected. Paths and provenance
must each fit 1024 bytes; source bytes fit 4 MiB. No payload heap allocation is
introduced; the importer reuses a 128-byte copy workspace. HAL file handles retain
their existing small fallible allocations. Inspection/validation uses small fixed
chunks instead of holding books or annotation lists in RAM.

## Archive format BSA1 (version 1)

All integers are little-endian; no native struct padding:

| Bytes | Meaning |
| --- | --- |
| 0–3 | ASCII `BSA1` |
| 4–7 | Kind: 1 clipping, 2 bookmark, 3 annotation anchor, 4 bookmark anchor, 5 download identity evidence |
| 8–11 | Raw source length |
| 12–15 | Source path length |
| 16–19 | Opaque provenance length |
| 20 onward | Exact path bytes, provenance bytes, then exact source bytes |
| Final 4 | IEEE CRC32 of every preceding byte |

CRC is a corruption detector, not a cryptographic identity or remote proof.
Idempotency compares the entire expected archive, byte for byte, including kind,
source path and provenance; it never deduplicates by CRC alone. Changed source or
account provenance requires a new archive path. Existing different or damaged
archives remain untouched, even if another candidate is valid. On restart an
identical completed current/backup archive returns `AlreadyPreserved` without
writes; incomplete staging is never proof and can be rebuilt through F06.
Source originals and backups are never removed. This archive is not permission
for source retirement, outgoing replay or acknowledgment of an uncertain delivery.

The owned recovery reader must support BSA1 before F29 uses it for activation.
Any future layout change needs a new magic/version, with recovery retained for
this version. No existing EPUB cache or native store layout changes here.

## Verification

Host tests compile production import/publication code with F03 fixtures. They
exercise all seven fixture variants, every truncation boundary, trailing bytes,
unknown/corrupt input, raw spans, BOB recovery/watermarks, two boots, account/source
conflicts, alias rejection, storage failure and cuts at each publication boundary.
The simulator scenario executes two independent processes on one synthetic SD in
each of the three profiles. SHA-256 inventories prove the entire F03 corpus,
including backups, corrupt and unknown files, remains identical; all completed
archives are identical on boot two. CI runs this through `test/simulator/boot.py`.
The linker retains the dormant importer in all real-image reserve checks.

Maintainer-only hardware verification after F29 supplies activation: on X4 Pro,
X4 Classic and X3/C3 X4, use a copied synthetic legacy SD, import twice and compare
original/backup hashes and archive bytes. Open a local EPUB, inspect a highlight
and bookmark, turn pages and reopen; expect unchanged location/selection behavior,
no network request and no new migration screen from F27b. Measure internal free
and largest RAM and worker stack high-water. No cache reset is needed. This slice
does not authorize device/serial access or claim hardware acceptance.
