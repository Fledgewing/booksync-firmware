# BookSync F26b: private credential import

F26b provides a worker-only read-only importer and an offline F15 restore seam.
It adds no screen, boot activation, radio operation, library writer or reader
change. F29 owns cutover admission, source inventory, account-store activation,
login removal/sign-out persistence and recovery. The default adapter remains
offline and reports unsupported restore until its private transport is supplied.

## Inputs and proof

The F03 corpus pins the 0.11 on-device formats and their provenance:
`/.crosspoint/bookorbit.json` (library sync), `koreader.json` (independent native
sync, cfgVersion 3), `opds.json` (independent acquisition servers), and `wifi.json`.
The caller supplies the original six hardware-key bytes; the importer neither
reads/replaces NVS nor generates a new identity/key. Only checksum-validated CPV1
is interpreted. Older XOR/plaintext/binary, future schema versions, wrong-device
keys, malformed/oversized input and incomplete credentials remain unresolved.
Unknown fields in a recognized document survive in the exact private source copy.

`Credentials::stage()` opens the legacy source with O_RDONLY and closes it before
opening any destination. Destination paths must be in `/.booksync/`, separate
from the legacy source, with the FilePublish `.tmp`/`.bak` suffix contract. F29
creates the private destination directory and serializes imports with other SD
work. A BSI1 snapshot stores family, length, CRC32 and every original JSON byte;
see `docs/file-formats.md`. The complete source bytes themselves are the identity
proof: a second import requires an exact comparison, including unknown fields and
whitespace. CRC32 detects torn/damaged copies; it is not an authentication claim.
No hash, identifier, URL, username, SSID or secret is logged. Never export this
private snapshot with diagnostics. CPV1 retains legacy obfuscation; it is not card
encryption. No real credentials belong in fixtures, commits or CI artifacts.

An existing owned snapshot is never overwritten, even if corrupt or unsupported.
Changed sources return Conflict; missing/unknown/corrupt originals and all backups
remain in place. Owned incomplete staging is never selected for restore. FilePublish
publishes a complete snapshot after file and directory barriers. Fault tests cut
all observed I/O boundaries, then repeat the import after restart.

## Restore and ownership

`restore()` revalidates a complete owned snapshot, decodes into reusable private
storage and sends a CredentialCapture through Account::restoreLogin. This calls
the adapter's separate local restore method, never authenticate. F15 performs its
existing sync wire normalization exactly once; a legacy sync password is never
submitted as a web/account password. Independent native sync and acquisition
retain their own origins and login kinds. Acquisition servers are selected by
bounded index; F29 must preserve their separate scopes, not iterate all of them
into one account slot. Current F15 process-local owners are allocated by the
private transport, never inferred from a legacy numeric server identifier.

Account restore fills only absent connector slots and cannot create a web-account
session or replace a current login. Failure preserves account state and erases the
capture. Empty origins return NeedsOrigin, including the unchanged F03 originals.
Legacy private access-token fields are preserved in the source copy and passed
as a borrowed, private LoginAuthorization value during synchronous local restore.
Only an adapter declaring additionalAuthorization can accept them; otherwise
restore returns Unresolved, without silently dropping protection or trying
another login. The same decode scratch is reused after the main secret has moved
into CredentialCapture, so this adds no workspace allocation. F29 supplies the
private transport and retains any unsupported result for later resolution. Native
custom header authorization likewise remains private and unresolved until a
matching adapter capability exists; unknown server-type enums are never coerced.

`restoreWifi()` stages the complete validated list through WifiTarget's
begin/add/finish transaction. A failed add or begin calls finish(false); targets
must erase candidates and preserve the previous saved networks. No join or scan
is requested. SSID (32), password (64) and network-count (8) limits are explicit;
open networks with an explicitly empty encoded password remain supported.

F29 must invoke restore only under its durable activation/account-store contract.
A frozen legacy proof is not the current credential store after sign-out or a
login edit; replaying it on every ordinary boot would revive removed credentials.
This slice deliberately installs no such boot hook.

## Resources and validation

One fallible, reusable workspace is statically bounded below 20 KiB, allocated
once per cold import job and released with that job. It replaces large task-stack
buffers; no static secret buffer or PSRAM assumption is introduced. The workspace
contains an 8 KiB source buffer, an 8 KiB fixed ArduinoJson arena, bounded CPV1
scratch and F15 capture. The arena implements bounded reallocation without heap
churn; overflow fails rather than truncating. Every operation erases copied JSON,
decoded material and captures on all normal/error returns. Local copy chunks are
128 bytes. No source/file handle survives a method call.

Run `python3 tools/ci/host.py`. The focused credentials target contains fourteen
production-code tests, including F03 inputs, two-boot local restore, explicit-login
protection, unknown/corrupt formats, source conflicts, publication cuts, full and
read-only cards and Wi-Fi rollback. `test/simulator/credentials.py <profile>` runs
two fresh processes on one synthetic SD for all three profiles: 36 checks per
profile with zero authentication requests, unchanged legacy bytes and unchanged
private snapshots on boot two. It uses F03 public fakes with synthetic nonempty
origins for the supported restore cases; it never reads a real card/NVS.
The scenario joins `test/simulator/boot.py` and the required firmware check.

The early link gate retains import/stage/restore, Account restore and private auth
normalization in all real images without running them at startup. The usual
measurement reports include complete ELF sections, map/symbol deltas against the
committed F14 baseline and the unchanged 128 KiB reserve gate. Native allocation
bounds, RSS and stack behavior cannot qualify ESP32 internal free/largest heap or
hardware stack watermarks.

Maintainer hardware verification belongs to F29 activation: use synthetic legacy
credentials on X4 Pro, X4 Classic and X3/C3 X4, import and restart twice, and verify
independent sync/acquisition sign-in and saved Wi-Fi selection persist with no
source changes. Test wrong-key/truncated/unknown files and card-write failures;
expect unresolved state with original bytes intact and saved books usable. Confirm
an explicit sign-out stays signed out after another boot. Inspect internal heap,
largest block and worker stack watermarks during import, including C3. No EPUB
cache reset is needed. Agents must not access devices or serial ports.
