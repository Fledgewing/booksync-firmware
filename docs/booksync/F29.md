# F29: retained upgrade activation and recovery

This implements the 2026-11-27 slim decision in BookSync #215. Only F26b
credentials/Wi-Fi and F26c Tailnet identity participate. No settings, positions,
annotations, stats, download mappings or queues are imported. Native reader
files and every legacy original/backup stay untouched. The approved B2 notice is presented once on Home, with Library-only actions.

## Cutover

`initializeUpgrade()` runs after SD mount, before activities and owned workers.
A read-only presence check before native recovery also recognizes signed-out
reader upgrades without mistaking newly created native directories for an upgrade.
It obtains the original eFuse credential key and audits NVS with Tailnet stopped.
One reusable fallible importer workspace (at most 20 KiB) stages validated BSI1
snapshots under `/.booksync/import/`. No network request is made. A 64-byte BSA1
record atomically activates only complete, verified snapshots and records
unresolved families. Backup-only or old binary credential sources remain unresolved
rather than silently reviving a login. The original JSON bytes remain in immutable private proofs.

Two sync scopes and up to eight separate acquisition scopes restore offline
through Account and the adapter's local restore seam. Sync wire normalization
stays inside the adapter. Restoring an independent connector never invents a web
account session or validates credentials remotely. The default transport remains
unavailable for remote authentication/catalog/lifecycle requests; this change
activates local credentials, not unreviewed outgoing delivery or legacy replay.
The normal F16/F18 jobs remain responsible for server restoration.

Boots after activation read owned proofs only. They do not inspect changed legacy
sources, overwrite a current login, or repeat the import. Unsupported/corrupt
activation/proof data keeps admission closed; original files remain available to
recovery tools. Saved books remain usable. Library publishes a bounded recovery
flag for unresolved retained state without exposing source values or secrets.

An imported connector installs an Account removal hook. Each connector and the
notice have a positively validated current BSL1 lifetime record. Restore requires
Live; a missing, damaged or unreadable current record never selects an older Live
backup. Initial publication cannot replace any existing current/backup authority.
Before clearing its live slot, removal publishes a permanent `removed-<scope>`
marker and commits the current lifetime state to Retired. A missing directory
barrier returns failure rather than claiming removal completed. Any existing
marker, including a torn or unreadable candidate, denies subsequent restore.
Markers never become reusable account credentials, and cannot affect another
scope. Losing a marker cannot revive a positively closed current state. Unknown
current lifetime state remains unavailable and is reported for recovery.
A validated complete removal receipt resumes only the interrupted transition to
Retired. Read-only/full storage keeps admission closed until it can finish;
ordinary boot never promotes a former Live backup. New explicit login handling must retain these retirement markers; they
permanently retire the old import rather than serving as a backup login.

Wi-Fi is copied once to the independent owned `/.booksync/wifi.json` before the
activation commit. Its runtime loader requires committed activation and reads
only its bounded current file. It never promotes a backup/temp or reads/migrates
legacy JSON/binary sources. Forgetting a network or losing the current owned file
therefore cannot replay the immutable import. Existing save primitives and Wi-Fi
hardware behavior otherwise remain in place. The private owned directory is
protected from plugin/file-transfer access alongside the legacy credential paths.

## Identity safety before and during loading

`NvsGuard.cpp` wraps `nvs_flash_init`, including Arduino's pre-setup call. It maps
the two errors that Arduino interprets as permission to format to generic failure.
The NVS partition remains physically untouched. Pre-Arduino logging uses the ROM
print primitive because the application logging/serial runtime is not ready.
Other initialization errors remain errors. This does not repair an unreadable
partition or authorize an empty identity.

Tailnet's neutral atomic admission gate stays closed until the boot audit matches
the activated identity fingerprint. Absent, incomplete, changed and unreadable
identity never authorize automatic generation. At every actual MicroLink load,
`RetainedKeys.h` opens read-only and requires six successful, exact 32-byte reads.
Any failure wipes partially copied keys, closes the handle and returns unavailable.
There is no generation, derivation, write, commit or ephemeral fallback.

`tailnet/retained_keys.py` replaces the pinned unsafe loader only in a build-owned
compilation input. It verifies the exact source digest and expected call site,
removes the implicit generator and fails on source drift. The dependency checkout,
MicroLink gitlink, NVS names/types and default device-name algorithm are unchanged.
This is reuse-only activation; new identity creation requires a separate explicit
pairing contract. No fallback erases or resets NVS.

## Notice contract

The activation record remembers whether an upgrade was detected. Library snapshot
publishes `upgradeNoticePending` from cached values: paint does no reads/writes.
`DismissUpgradeNotice` queues the worker checkpoint for either future B2 choice
(Back/Later or normal-sync action). A distinct immutable `notice-done` marker
and positively closed notice lifetime state prevent an old activation backup
from reviving the notice. A partial/damaged
marker suppresses presentation conservatively and remains on disk for recovery.
The B2 screen uses Library values and intents only. Now submits `Sync` and dismissal;
Later and Back submit dismissal only. The coordinator explicitly accepts an offline
`Unavailable` sync result without an error screen. Adapter-to-Library integration
is not assigned an explicit slice in PLAN.md; F16/F17/F18/F21 supply its parts.

## Resource and verification evidence

Activation itself owns a small static record and ten removal-hook contexts. The
independent Account values contain readiness/epochs and hook pointers, not retained
plaintext. No new activity/task or steady-state credential workspace is allocated.
The 20 KiB temporary workspace is too large for the C3 task stack; it is reused
for every family and wiped/freed before Home/reader allocation. Marker path buffers
are bounded below 256 bytes. Existing cold JSON loading uses its caller-selected
8 KiB input bound. Simulator allocation/stack metrics do not qualify ESP32 memory.

`python3 tools/ci/host.py` includes production-code activation tests, the Library
paint/worker checkpoint contract, current-only credential recovery tests, strict
loader read failures and the pre-Arduino error guard. The activation tests cut
all observed fake-card I/O events, both buffered and eager metadata persistence,
plus recoverable I/O failures, full/read-only cards, corrupt formats, fresh installs,
repeated boots, removal, forgotten Wi-Fi and changed identity.

`test/simulator/activation.py <profile>` runs the actual firmware boot path with
synthetic SD/identity and fake transport. It hard-exits before/after every observed
publication checkpoint, reboots twice, verifies account scope, notice state,
sole-writer rejection and every original SD byte. Removal and Library dismissal
have their own full cut matrices. Separate backup-recovery matrices retain torn
owned primaries unchanged and prove that old activation backups cannot revive
a dismissed notice. Fresh and signed-out reader-only boots cover notice eligibility. The F26c production NVS audit fault scenario and
F10 identity tests run alongside it in all three profile gates. No failed scenario
is retried into success. Reports record counts, never source credentials or identity
fingerprints. Six builds, image/ELF/map measurements and the unchanged 128 KiB
reserve gate remain required.

Maintainer-only hardware verification: on X4 Pro, X4 Classic and X3/C3 X4, upgrade
synthetically provisioned readers, restart repeatedly and confirm saved Wi-Fi,
independent connector readiness and the same Tailnet node/pairing. Forget a login
and a network, reboot and confirm neither returns. Inject incomplete/unsupported
NVS and SD write/read failures; expect unavailable retained state without formatting,
key generation, re-pairing or a second writer. Open/read/close/resume the same local
book through failures and compare native files. Inspect internal free/largest RAM
and boot/worker stack watermarks. No EPUB cache reset is needed. No device or
serial port is accessed by this implementation or its automated tests.
