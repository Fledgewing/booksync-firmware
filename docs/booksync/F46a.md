# F46a: default adapter and admitted HTTP transport

The default factory now registers the concrete BookOrbit adapter. The existing
Library facade still boots from its local index without network. F46c connects
its Sync intent and background opportunities to this worker-only adapter; F46b
supplies native evidence, and F46d schedules copy replacement. This increment
adds no screen, automatic sync, lifecycle delivery or reader change.

F29 restores independent sync and acquisition logins offline. The adapter now
retains bounded private copies instead of discarding those credentials. Each
connector has a non-reused process-local owner; removing it identifies both kind
and owner. Account sign-out continues to preserve independent user connectors.
Selecting an unknown connector clears the old selection and cannot fall back to
another login. No web account session is invented. Authentication forms remain
owned by their separate account slice.

Catalog requests reuse F16's streaming parser through a bounded HTTP body cursor.
The pinned SDK verifies Content-Length/chunk framing while streaming into one
disposable SD spool, capped at 4 MiB. The cursor exposes the body only after framing
and file close succeed. A disconnect, oversized response, storage failure or
revoked permission cannot become a successful empty catalog. No response-sized
RAM allocation is introduced, and the spool is never an authoritative generation
or a recovery source. F21 still owns generation publication.

Every concrete HTTP operation checks network admission. The worker closes the
connection before returning; ReadingGate revocation aborts between SDK operations.
Redirects are never followed, so private headers cannot move to another origin.
Origin normalization preserves the existing optional scheme, reverse-proxy prefix
and pasted API suffix behavior. Additional imported authorization is Cloudflare
Access, sent only over HTTPS; it is never treated as Basic or OPDS authentication.
HTTPS requires certificate verification with the existing BookSync ISRG X1/X2
roots. No insecure fallback or new trust-confirmation screen is introduced. F46b
provides retained native trust-anchor evidence before F46c enables scheduling.
SDK-owned request-header references are released after each request.

Resource bounds: absent connector slots cost only ten owned pointers. Each present
login needs one fallible allocation below 3 KiB because its caller erases borrowed
buffers after restore. The at-most-ten slots are erased on local removal or adapter
destruction. The catalog cursor needs one fallible allocation below 5 KiB per
worker session, reused across pages and freed by endSyncSession before reading.
The generic HAL also owns one fallible SDK control object below 2 KiB per worker
session and rechecks cancellation throughout framing. SDK URL/header allocations are bounded cold request work, with no per-row payload
allocation. No task, second framebuffer or PSRAM assumption is added.

Host tests cover private connector selection/removal/capacity, offline restore,
header injection and authentication failure, plus the production SDK HTTP parser
and body spool under complete, truncated, chunked, oversized, redirect, full-card,
ReadingGate and additional-authorization cases. The UI-only compile/link contract
still uses an unavailable HTTP fixture while linking the production factory and
adapter. Its screens receive no private headers or transport symbols.

The three simulator profiles run live_adapter.py through the real admitted
network worker and SDK HTTP client. CI supplies a socket fixture and a matching-host self-signed TLS peer that must
receive no authenticated HTTP request. For the seeded
existing tools/e2e server, point BOOKSYNC_LIVE_ORIGIN at its isolated fault proxy
and provide its synthetic BOOKSYNC_LIVE_USER and BOOKSYNC_LIVE_KEY; the same
scenario exercises the real adapter and validates success and expired credentials.
The remaining first-sync/account-switch/power-cut lifecycle cases belong to F46b/c,
and copy-replacement scheduling to F46d. Simulator memory is not device evidence.

Maintainer-only hardware verification after F46c: on X4 Pro, X4 Classic and X3,
choose the service with a retained synthetic sync login, request sync at Home,
then verify the published catalog remains usable offline and expired credentials
retain the previous generation. Open a local EPUB during a request to verify
cancellation and unchanged native place, page turns and annotations. Check internal
free/largest heap and worker stack watermarks, including C3 display restoration.
No EPUB cache format changes or cache reset are needed. Agents do not use devices
or serial ports.
