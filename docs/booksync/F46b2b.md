# F46b2b: native annotation persistence

This component supplies checked annotation records, immutable captures/complete
reply spools, native bookmark identity retention and an exact-key closed clipping
projection seam. The concrete F18 workspace, replica mapping and durable per-row
receipts follow in the next small PR. Automatic delivery remains off until the
live worker integration. No screen, network trigger or additional writer is added.

`AnnotationSpool` binds every publication to the complete opaque account/server,
source book/edition/revision, delivery entry, native open, bound payload and document.
The owner must prove the actual closed source with `NativeCaptureGate` before
using this container; valid framing is not authority. An admission callback can
revoke work between records. Positive loads confirm the filesystem barrier.
Unknown/damaged current files and staging/backup files cannot authorize replay.

A complete reply contains up to 600 streamed `BAR1` records, including raw unknown
locators, text, notes, presence bits and deletion operations. Captures support
1,024 rows/keys. All bytes are staged and validated before publication. The round
counter is independent of the outgoing cursor. A known-empty first key set is
separate from omitted keys in subsequent exchange rounds. Existing small-array
phase implementations remain compatible with the streaming interfaces.

One caller-owned 32 KiB buffer is reused for records and blocks of keys; a complete
1,024-key iteration needs two data-file opens. Codec headers and control metadata
stay in the provider object. The eventual worker allocates optional workspaces
once per phase, releases them before reading and never allocates on paint. The
physical-image budget root retains all concrete code without a startup caller.
New codec/spool compiler frames have a 512-byte gate; native store frame reports
are collected separately. These are not hardware heap/stack acceptance results.

Native bookmark records remain 128 bytes in RAM. Their existing padding stores
only offsets into SD UUID fields. New bound native actions may obtain independently
issued UUIDs from an optional issuer; absent/failed issuance keeps them local.
Old rows never acquire identity merely by loading or matching coordinates. Native
edits and four-source path migration preserve existing UUID bytes. Native user
mutation versions and hidden empty markers prevent a later delete from resembling
an earlier missing/empty store. Saturation must exclude background projection.

Closed clipping projection matches only an exact scoped `NP1:` key after source
and reader exclusion by its caller. Equal text and old connector keys do not bind
rows. Unrelated native rows/deletion strings remain intact, older formats defer
to native migration, producer echo is suppressed, and staging, publication and
backup retirement each require the supplied durability barrier. Failure produces
no application receipt or acknowledgement.

Formats and the read-only recovery inspector are documented in
`docs/file-formats.md`. The inspector validates one bounded record at a time and
prints only format/count/size metadata, without repair, network or disclosure of
reading content. Local publication evidence never proves a remote commit.

Verification includes native store preservation/rollback, deletion/re-add identity,
220 empty markers with an active book, maximum raw fields, large streamed replies,
revoked admission, every publication cut, incomplete/corrupt/conflicting files,
filesystem barrier failures and independent recovery vectors. The simulator uses
real HAL files across capture, 600-row stage, abrupt cut and restart processes on
Pro, Classic and X3, and independently inspects the published records. These
provider scenarios receive synthetic normalized replies and perform no network.
The later live integration must run the separate fake-server end-to-end flows.

After live integration, maintainers should create/edit/delete a bookmark and
highlight on Pro, Classic and X3, restart between staging and acknowledgement,
then delete the final bookmark before replay. Expect native edits and unrelated
rows to survive, deletion to stay deleted, and account/source switches to defer
old work. Check internal free/largest heap and worker stack high-water, plus PSRAM
on S3. No EPUB cache reset is required. This component accesses no device or
serial port.
