# F09 local reader capture

The native EPUB, XTC and TXT readers observe open, live page/source coordinates,
accepted native reading counters and close through `reader/Bridge`. Main-loop
polls take a nonblocking RenderLock; close uses the existing lock or waits for it.
Paint never invokes BookSync. No network, delivery, acknowledgment, UI or second
reading timer is added. Native stats, session, progress and annotation formats,
paths, save decisions and return values stay owned by CrossInk.

One main-task capture writer uses F07 at `/.booksync/reader.journal` with its
reserved `.tmp`/`.bak` siblings. Native annotation publication invokes an optional
observer only after the original publication succeeds. Exact bookmark/highlight
file bytes (including anchor versions, scoped keys, deletion records and unknown
fields) are copied in bounded parts; clearing bookmarks records a deletion.
Absent observers leave native storage independent, including retained host tests.

Each open has one F07 ID. Its checkpoint replaces the last complete observed
page/time snapshot, rather than appending every page turn. An interrupted open
stays unclosed; reboot starts a different open and never fabricates a close.
A failed update leaves the preceding complete checkpoint. Unaccepted dwell time
is never invented. A cut can lose an observation not yet checkpointed, just as
native capture can lose its uncommitted interval; capture makes no promise of
counting time after the last accepted native interval.

Local capture uses the neutral `native` / `local-unbound` namespace. A path is
source evidence, never a BookId, edition, account or exact-file revision. F08
canonical matching must supply verified identities before later delivery can
interpret a raw locator. Current live source offsets are separate from the exact
native progress slots, including their sequence, CRC and offset-presence flags.
No percentage conversion, cross-edition mapping or remote replay occurs here.

Native timed-session IDs, document IDs, UTC boundaries, accepted seconds and timezone offsets are also copied from a read-only native session view. Each native session keeps its own cumulative F07 checkpoint; a new native ID appends a separate record. Native flush and timing rules remain unchanged.

Native totals, native session seconds, session counts, counter IDs and the
opening total/counter are stored separately. At native commit, session seconds
can reset while the total increases. A future provider must reconcile that
baseline/counter identity instead of adding aggregate and session coverage twice.
TXT has no native stats timer; its stats presence remains false.

## Internal capture records, version 1

These are local observation envelopes within F07, not a frozen export or adapter
protocol. All integers are little endian; there is no C++ struct serialization.
Unknown versions must remain retained and unresolved.

- `BSO1`: magic, native format u16 (EPUB 1, XTC 2, TXT 3), path length u16,
  then exact UTF-8 path bytes (1–1024). F07 assigns the durable open ID.
- `BSC1`: 116-byte checkpoint: magic; closed/source-offset-present/stats-present
  bytes and one reserved zero; seven u32 values (spine, page, page count, source
  offset, native total seconds, native session seconds, native forward turns);
  16-byte native counter ID; two 20-byte raw progress-slot areas; their u8 lengths;
  u16 native session count; u32 opening total; 16-byte opening counter ID.
  Length zero is absent, distinct from a known zero offset. Each slot is inspected
  through its native decoder, such as F08's `epubAnchor`, after identity resolution.
- `BSS1`: 90-byte native session observation: magic, 32 exact native session-ID
  bytes, 32 native document-ID bytes, u64 start/end UTC seconds, u32 accepted
  seconds, signed i16 UTC offset in minutes. Payload records the first observation;
  checkpoint holds the latest cumulative observation with the same native ID.
- `BSA1`: 32-byte part header: magic, deleted byte, terminal byte, kind length
  u16, book-path length u16, first-part F07 ID u64, offset u32, total u32,
  part length u16, four reserved zeros; kind, book path and exact native bytes.
  First part uses group zero and its own F07 ID; following parts reference it.
  Parts contain at most 2048 native bytes. Only a contiguous complete sequence
  with a terminal part represents a snapshot. Incomplete groups remain pending;
  they are never an empty annotation set or an acknowledgment.

Whole-snapshot entry and byte capacity is checked before the first part. F07
still checks every publication. Capacity, read-only/full card and I/O errors are
logged, never evict unacknowledged data or change native save success. An I/O
failure can leave an incomplete group; native originals are untouched. Recovery
and later capacity presentation/delivery belong to their planned services.

## Resource bounds and verification

Capture introduces no heap allocation. Shared main-task scratch is 1032 bytes
for the open envelope plus 3136 bytes for an annotation part (4168 total), avoiding
large task-stack buffers and per-turn allocations. One small Capture value lives
inside each existing reader activity. Native HAL file handles remain fallible
HAL-owned allocations. No source reader remains open while F07 writes a generation.

`ReaderCaptureTest` covers checkpoint cuts, capacity, read-only failure, native
source preservation, multipart bytes, counter baselines and F03/F08 raw locators.
`test/simulator/reader_capture.py` adds native read/close and mid-session process
cut/restart scenarios to every F02 profile. The unchanged F03 baseline and F05
fake transport scenarios remain required. Host memory numbers do not qualify
ESP32 internal heap, largest free block or stack headroom.

Maintainer hardware verification (agents do not touch devices): on X4 Pro,
X4 Classic and X3/C3, read a synthetic EPUB offline, turn after a qualifying dwell,
add/remove a highlight and bookmark, close and reopen. Compare native files and
UI with the baseline, then cut power during a later session and verify the last
complete local capture and native anchor on reboot. Inspect free internal heap,
largest block and task stack watermark; S3 also needs PSRAM measurements. No
cache reset is needed because native formats/layout are unchanged. This is not
release or device-acceptance evidence.
