# F26a: read-only settings candidates

`import/Settings.*` inspects the 0.11 on-device formats recorded by F03's
`test/fixtures/legacy/inventory.json`. Its source pins remain the format authority.
This is dormant worker code, included in the hardware full-link gate. There is
no boot call, settings application, screen, PIN unlock/recovery, network operation,
NVS write, source retirement or reader change. F29 owns selection and activation;
F38 owns settings services and their Library presentation.

## Evidence and restart contract

The caller inventories each source separately: current native JSON, its backup,
the older JSON path, sleep JSON, the three plain option files, and historical
settings/language binary slots. No primary/backup priority or repaired default is
invented here. Old binary layouts are retained as unsupported, without guessed
parsing. Native and sleep JSON are unversioned; a top-level version/schema envelope
is unsupported. Unknown JSON fields remain available to the import worker and
remain byte-exact in the original and raw backup. Never reserialize the candidate
to replace raw evidence.

Before exposing a candidate, the importer verifies a raw copy under
`/.booksync/import/settings/`. The caller creates that directory and assigns a
unique raw destination per source. Destination filenames cannot contain directory
separators or traversal; legacy paths cannot be publication destinations. F06
publishes only that owned copy. All legacy file handles are read-only and explicitly
closed. An existing matching copy is reused without writes; different or unreadable
evidence is never overwritten to make an import succeed. A torn owned staging copy
can be reconstructed on the next boot, while the legacy source stays intact.

Proof version 1 exposes the exact source byte length, SHA-256, source path/kind and
selected raw-backup path. A successful raw copy is additionally compared byte by
byte; equality does not depend on a hash collision assumption. F29 must durably bind
these values and the parse status in its activation proof. Caller-owned source
bytes and destination strings must remain valid throughout the call; exclude other
writers to those sources and destinations until the call completes. Borrowed
candidate views expire on the next read or destruction. The proof is not an
activation or an acknowledgment.

Missing, corrupt, unsupported, unresolved-enum, I/O and backup-conflict statuses are
distinct. A parse or publication failure exposes no applicable JSON candidate.
An unresolved enum preserves its raw candidate for review; it cannot authorize
application. Missing keys remain absent. Known persisted enum numbers remain distinct
from UI option indices, including publisher-font mode 2 and hidden progress/title
values. Word and character spacing expose signed levels alongside their raw bytes.
Old font steps map to their native point sizes (including card-font range context),
and retired card-font range 3 maps to range 4 without changing the raw value.
Unknown numbers/types are never clamped or replaced with defaults.

The settings PIN is the exact `crossink_pin` / `v1` opaque 48-byte salt/hash record.
The production NVS path uses only `NVS_READONLY`, get-blob and close. No PIN digits,
key derivation, identity generation, erase, commit or recovery-file handling is
involved. Unknown-length records up to the workspace budget also receive a raw
copy and remain unsupported. Larger blobs remain untouched in NVS and block a
complete proof; absence or a failed read never clears an existing lock.

## Bounds and verification

One reusable workspace contains a 24 KiB fixed ArduinoJson arena; JSON input is
capped at 16 KiB with nesting limited to 12. There is no payload heap allocation,
PSRAM dependency, full-file buffer or permanent hardware workspace allocation.
F29 must keep this roughly 25 KiB object off the small task stack, for example by
one checked `makeUniqueNoThrow<Settings>()` allocation for its worker lifetime.
The arena returns allocation failure rather than growing. Raw copying/comparison
and hashing use 64–128-byte chunks. The cold SHA context plus chunk can exceed
256 stack bytes on host crypto implementations; it does not scale with input size.
Native simulator SHA uses real platform crypto, not its placeholder hash stubs.

Host tests compile production code against faultable HAL and read-only NVS stubs.
They cover F03 enums, original/backup/old paths, sleep and plain choices, opaque
PIN preservation, exact SHA evidence, unknown/corrupt/oversized formats, arena
exhaustion/reuse, every publication interruption and I/O failure, full/read-only
cards, backup conflicts and forbidden destinations. The NVS stub intentionally
has no mutation functions, so adding a write fails compilation/linking.

`settings_import.py` runs current, unknown and corrupt F03 settings through two
independent simulator processes before native settings/session boot loaders in each of the three profiles (9 scenarios,
18 boots total). It fingerprints the entire seeded legacy SD/NVS inventory and
requires every source, sign-in/pairing fixture and path to remain unchanged. Both
raw settings and PIN backups must match, and boot two must change no file.
Simulator logs report workspace/arena bounds; hardware internal heap, largest
block and task watermarks are not representable acceptance evidence here.

Run `python3 tools/ci/host.py`, build `x4-pro`, `x4-classic`, `default` and their
three simulator profiles, run `python3 tools/ci/measure.py <hardware-profile>` and
`python3 test/simulator/boot.py <simulator-profile>`. The size gate requires the
dormant importer symbol as well as the existing retained pipeline.

Hardware verification is maintainer-only: on X4 Pro, X4 Classic and X3/C3 X4,
boot twice with a retained 0.11 card/NVS snapshot, read/turn/close/reopen a local
EPUB and confirm unchanged settings, lock, paths, sign-in/pairing and native reader
position. This slice does not start import at boot; F29 must separately verify
activation against the original snapshots, raw fingerprints and settings values.
No EPUB cache reset is needed. Agents do not access devices or serial ports.
